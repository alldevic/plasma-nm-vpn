# 2.5 sing-box config

**Stage:** 2 · **Duration:** 2 d · **Depends on:** 2.2, 2.4, 1.4 · **Needed for:** 2.7, 6.6

## Goal
Generate the sing-box config for Hysteria2 from validated profile fields so that only our template for the pinned version reaches the core. Golden tests pin the output and catch discrepancies when the core is updated.

## Inputs
- The typed profile structure and the allowlist loader from 2.2.
- From 2.4: the TUN name (a persistent TUN created by the daemon), the /30 address, the server IP, the parent device name. The generator receives them as input; in golden tests they are fixed values.
- The integration bench in `tests/integration/stand/` from 1.4 (extended here with port hopping).
- The findings of 0.4 on how sing-box attaches to an existing persistent TUN (flags, any keys needed).
- [design.md](../design.md), section “Profile data schema”: Hysteria2 keys (`ports` in the link format, `hop-interval`, `obfs`, `tls-sni`, `tls-alpn`, `tls-insecure`, `tls-pin-sha256`, `up-mbps`, `down-mbps`; secrets `password`, `obfs-password`), `extra`, `mtu`.
- [design.md](../design.md), sections “Routing, DNS and IPv6” (`auto_route: false`, `bind_interface`), “Daemon security”, “Protocols and backends” (sing-box 1.14.4), item “Paths” (`/usr/share/plasma-nm-vpn/`).

## Tasks
- [x] A template for sing-box 1.14.x (the version from the package, currently 1.14.5) in `/usr/share/plasma-nm-vpn/`, JSON via json-glib with a stable key order:
  - `log`: level and output to stdout/stderr (ends up in the unit's journal);
  - `tun` inbound: `interface_name` = `pnv-…`, `address` = the address from `Ip4Config`, `auto_route: false`, `mtu` from the profile; `stack` per the findings of 0.4 and 0.7; whatever 0.4 found necessary for attaching to the existing persistent TUN rather than creating one;
  - `hysteria2` outbound: `server` = the server IP (not the name), ports (see below), `password`, `up_mbps`/`down_mbps`, `obfs` with `type: salamander` and `password`, `tls` (`enabled`, `server_name` = `tls-sni` or the server name, `alpn`, `insecure`), `bind_interface`;
  - `route`: everything to the Hysteria2 outbound.
- [x] Converting `ports` from the link format (`443` or `443,5000-6000`) to the sing-box format: a single port → `server_port`; a list or ranges → `server_ports` with `hop_interval` from `hop-interval`. Check the format of `server_ports` elements (apparently `5000:6000`) and whether `server_port` is still needed in that case against the 1.14.x documentation and `sing-box check`.
- [x] `tls-pin-sha256`: check whether sing-box 1.14.x TLS has a field equivalent to Hysteria2's `pinSHA256` (a hash of the certificate, not the public key). If not, the generator rejects profiles with this field, and the consequences are listed for design.md (to be updated there, not here): the key in “Profile data schema” (dropped from the Hysteria2 keys, or kept and rejected by the validator), the pin field of the TLS block in “plasma-nm user interface” (6.1 leaves it out), and the import of `pinSHA256` from `hysteria2://` links (6.6 reports it as unsupported instead of filling a field).
- [x] `extra`: an allowlist of Hysteria2 outbound keys for 1.14.x (a data file in the format from 2.2, installed by the `plasma-nm-vpn-sb` package). Do not include keys set by the generator (server, ports, password, `bind_interface`), file paths or `detour`. Merge only into the outbound object.
- [x] The secrets `password` and `obfs-password` end up only in the config in `/run/plasma-nm-vpn/<uuid>/`; logging functions do not print the config.
- [x] Golden tests: a set of profiles (minimal; single port; ports with a range; Salamander; ALPN and insecure; `extra`; `mtu`; SNI different from the server; IPv6 server) → expected JSON in the repository, in a directory named after the sing-box version.
- [x] Test step: every golden file is run through `sing-box check -c <file>` of the pinned binary.
- [x] Port hopping on the server bench (deferred from 0.3): extend `tests/integration/stand/` (1.4) with an nftables DNAT rule in netns `stand` that redirects a UDP port range (for example, 20000–20100 on 198.51.100.1) to the hysteria2 server's UDP port 443, and a test profile with `ports=443,20000-20100`.
- [x] Wire the generator into the daemon in place of the temporary config from 2.3.

## Deliverables
- The Hysteria2 config generator and template in the `plasma-nm-vpn-sb` package; the `extra` allowlist for 1.14.x.
- Golden files and tests, including `sing-box check`.

## Done when
- [x] `ctest` → the golden tests pass; changing any template field fails the corresponding test.
- [x] `sing-box check -c` exits with code 0 for every golden file.
- [x] The `tls-pin-sha256` finding is recorded: either the field maps to a sing-box key covered by a golden test, or profiles with it are rejected and the list of design.md consequences is written up.
- [x] A profile with `detour` or a file path in `extra` → the generator rejects it.
- [x] In the VM the daemon brings up Hysteria2 to the test bench with a generated config, both with a single port and with port hopping (the DNAT counters in netns `stand` show packets on ports from the range).

## Risks and notes
- The sing-box config format changes from version to version, so golden files are stored per version, and a core update (1.5) starts with regenerating them and reviewing the diff.
- The address in the TUN inbound matches the address NM sets from `Ip4Config`; if sing-box and NM conflict when setting the address, this shows up here already, in the VM.
- `gecko` obfuscation, `ech` and `hysteria2+realm://` are not supported in the MVP (design.md, section “plasma-nm user interface”); the generator does not know about them.
- Results:
  - Code: `backends/sb/daemon/config.c` fills the template `backends/sb/data/hysteria2.json`; the template and the `extra` allowlist `hysteria2-extra.list` are installed to `/usr/share/plasma-nm-vpn/sb/` by `plasma-nm-vpn-sb`. The daemon now uses the generator instead of the temporary config. json-glib keeps the template's member order, and added members follow it, so the output is stable.
  - Ports, checked with `sing-box check` on 1.14.5:
    - a single port → `server_port`;
    - a list or a range → `server_ports` only, with every element `a:b` (a lone port in the list is `443:443`; `"443"` fails with “bad port range”), plus `hop_interval` (`<n>s`, default 30 s).
    - `server_port` next to `server_ports` is accepted but not needed.
  - `tls-pin-sha256`: sing-box 1.14 has no certificate-hash pin. `pin_sha256` and `certificate_sha256` are unknown fields; `certificate_public_key_sha256` pins the public key. So the generator rejects such profiles, and the consequences are in design.md (“Profile data schema”, the TLS block row, the `hysteria2://` import).
  - `extra` allowlist for 1.14.x: `network`, `connect_timeout`, `udp_fragment`, `tls` and `tls.{disable_sni, min_version, max_version, cipher_suites, curve_preferences, certificate, certificate_public_key_sha256, fragment, fragment_fallback_delay, record_fragment}`; all accepted by `sing-box check`. `extra` objects merge into the generator's ones (`tls`).
  - Golden tests: `tests/golden/sing-box-1.14.5/`, 9 profiles → JSON (`PNV_GOLDEN_UPDATE=1` rewrites them after review), as ctest `sb-config`, which also checks that `extra` with `detour`, a `*_path`, `server` or `bind_interface` is rejected and that a pinned profile is refused. `scripts/check-golden` runs `sing-box check` on every golden file with the pinned binary; it runs in the `packages` job after the cores are fetched.
  - Port hopping on the bench: DNAT of UDP 20000–20100 on 198.51.100.1 to port 443 (chain `hop` in `table inet stand`, with a counter). `test_port_hopping` (`ports=20000-20100`, `hop-interval=5`) passes traffic, and the counter grows. Both the single-port and the hopping profile connect with the generated config.
  - In the local VM the snapshot had sing-box 1.14.4; it was replaced by the pinned 1.14.5 (sha256 checked) for these checks.
