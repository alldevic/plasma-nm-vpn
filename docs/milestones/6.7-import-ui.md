# 6.7 Import UI

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 6.6, 6.3–6.5 · **Needed for:** 6.8

## Goal
A profile is created by pasting a link or opening a `.conf` directly in our editor. This fulfills the requirement “links and configs are imported with a button”, which plasma-nm's stock “Import VPN connection” cannot fulfill. The milestone builds the shared import widget on top of the 6.6 parsers and wires it into the three editors.

## Inputs
- The 6.6 parsers (result: `vpn.data`, `vpn.secrets`, service type, warnings and errors as message codes in the parser group of the shared C code list) and the input size limit recorded in design.md; the message code rendering table and its coverage test from 6.1, which so far cover only the validator codes.
- The integration bench from 1.4 (links and `.conf` files for its servers; the bench DNS 203.0.113.1).
- The 6.3–6.5 editors: form blocks, `PasswordField` secrets.
- [design.md](../design.md), section “plasma-nm user interface”: why import is built into the editor, the “Paste link or config” field and the “Open file” button, the rule for parameters that are not in the form, message codes rendered by the editors through ki18n.
- [design.md](../design.md), section “Profile data schema”, item “Secrets”: import puts the secrets from a link into `vpn.secrets`.

## Tasks
- [x] Parser code rendering: add a ki18n entry (`i18nc` with the parameters) to the 6.1 rendering table for every code in the parser group of the shared code list, and extend the 6.1 coverage test to that group.
- [x] A shared import widget in the `plasma-nm-vpn-common` widget library, no plasma-nm internal API. Strings via ki18n.
  - A “Paste link or config” field (multi-line, so a `.conf` can be pasted too) and an “Import” action.
  - An “Open file” button (`QFileDialog`); a file over the 6.6 size limit is refused before it is read in full.
  - A warnings area (`KMessageWidget`): the list of unsupported or dropped parameters and of those moved into `extra`; parser errors are shown in the same area. Every entry is a 6.6 message code rendered through the entries added above, so it is translated like the rest of the UI.
- [x] Wiring into the 6.3–6.5 editors:
  - the parse result fills the form blocks and the `PasswordField`s; secrets from the link keep the `PasswordField` default storage (StoreForUser when a keychain is available; the import does not set it), empty optional secrets get “Not required”;
  - a link for a protocol other than the editor's → a message naming the entry to choose in the “Add VPN” list; the form is unchanged;
  - if the form already has filled-in fields, ask for confirmation before replacing them; on “No” nothing changes;
  - after import, the form is validated as if typed by hand (`isValid()`, change signal);
  - after a successful import the paste field is cleared, so a pasted link with secrets does not stay in it; after an error it is kept for correction.
- [x] The profile name is not set by import: plasma-nm's `ConnectionEditorBase::setting()` overwrites the id with its own connection name field, so `#name` from a link is not carried over.
- [x] Widget tests (QtTest, offscreen): the extended coverage test (every parser code has a rendering entry); pasting a sample link fills a test form and clears the paste field; confirmation before replacement; a wrong-protocol link leaves the form unchanged and keeps the paste field.

## Deliverables
- The import widget in `plasma-nm-vpn-common`, wired into the three editors, with tests.

## Done when
- [x] The 6.1 coverage test extended to the parser group → green in CI; no raw parser code is shown anywhere in the import UI.
- [x] A Hysteria2 link from the bench pasted into the editor in the VM → the form is filled in; with DNS 203.0.113.1 set in the “Protection” block before connecting, the profile connects from the applet. The same for `vless://`; an AmneziaWG `.conf` via “Open file” connects as imported.
- [x] After a successful import → the paste field is empty; after a failed one → the pasted text is still there.
- [x] An AmneziaWG `.conf` without `DNS` → the DNS field stays empty; the profile connects and, as a default-route tunnel, gets the default DNS from the daemon (`nmcli -g IP4.DNS connection show <id>` → 1.1.1.1 and 9.9.9.9).
- [x] A `.conf` with `PostUp`, `Table`, IPv6 in `Address` and two IPv4 addresses → the user sees a warning listing the dropped items.
- [x] A `.conf` with two `[Peer]` sections, a link with `obfs=gecko` or a `vless://` link in the Hysteria2 editor → a clear message, the form is unchanged.
- [x] Importing into a filled-in form → a confirmation prompt; declining leaves the form unchanged.

## Risks and notes
- Our plugin does not support plasma-nm's stock “Import VPN connection” (`supportedFileExtensions()` is empty); this is a design.md decision, and its effect is checked in 6.9.
- The bench has no internet, so imported Hysteria2 and VLESS profiles (links carry no DNS) get the bench DNS 203.0.113.1 before connecting, as every bench test profile does (0.3): with the defaults, 9.9.9.9 is unreachable on the bench and slows the resolver down, and the tests want one known DNS server. The liveness check (5.4) is not the reason: with the defaults it queries the first one, 1.1.1.1, which the bench answers. An AmneziaWG `.conf` connects as imported; one without `DNS` gets the defaults, which are checked only at the NM level.
- The clipboard itself is not cleared: it belongs to the user, and Klipper may already have the link in its history.
- Results:
  - **Rendering.** A ki18n entry for each parser code; the 6.1 coverage test now runs over the validator and parser groups. A warning `to-extra` was added to the parser group (6.6), so the user also sees what went into `extra`.
  - **The widget.** `PnvImportWidget` in the widget library: a multi-line paste field, “Import”, “Open File…” (`QFileDialog`; a file over 64 KiB is refused by its size, before it is read), and a `KMessageWidget` for the outcome:
    - “Imported. Check the fields before saving.”;
    - “Imported, with these changes:” and the warnings;
    - “Nothing was imported:” and the error;
    - for another protocol, “This is a VLESS XHTTP Reality connection: add it as “VLESS XHTTP Reality” in the list of VPN types.”
    The paste field is cleared after a successful import and kept after an error or a declined replacement.
  - **Wiring.** `PnvEditorWidget::addImport()` puts the widget in an “Import” group under the banner, with the lists of the editor's daemon. `applyImport()` asks before replacing a form with a server or a secret (`QMessageBox`; tests set the answer). It then loads the blocks and the secret fields, keeps their default storage, sets empty optional secrets to not required, and emits `validChanged` and the change signal. The `#name` of a link is not used.
  - **Unit tests.**
    - `tests/unit/widgets/test_import_widget.cpp`, 11 cases: a pasted link fills and clears; a declined replacement keeps the text; another protocol names the entry; four errors rendered and the text kept; warnings listed as a warning; an oversized file refused; a `.conf` file imported.
    - The Hysteria2 editor tests gained an import into an empty form (valid, field cleared, `validChanged(true)`) and the confirmation (declined: unchanged; accepted: replaced, optional secret not required).
  - **Without a desktop.** `tests/integration/cases/test_97_import.py`, 8 cases; the driver gained `importFile=`, and it reports the import message. Checked:
    - the bench's Hysteria2 and VLESS links pasted, connected, with DNS through the tunnel;
    - the bench's AmneziaWG `.conf` opened as a file, with an `Address` added (the bench file has none), connected with a handshake, `dns` left empty and `IP4.DNS` 1.1.1.1 and 9.9.9.9 from the daemon;
    - the Done-when `.conf` (`PostUp`, `Table`, IPv6 and two IPv4 addresses) lists the four dropped items;
    - two peers, `obfs=gecko` and a `vless://` link in the Hysteria2 editor give their message and save nothing.
    - Note: the imported secrets keep the user-keychain default, which needs a desktop agent; the root driver sets them to all users.
  - **On the desktop (local VM).** A VLESS link with `pcs` was put on the clipboard (through Klipper's D-Bus) and pasted into a new VLESS form in System Settings. “Import” filled the form with the UUID masked and stored for this user, cleared the paste field, and showed “Imported, with these changes: pcs is not supported here and was dropped”. With DNS 203.0.113.1 entered by hand, the profile saved (`uuid-flags=1`, the UUID in KWallet) and connected from the applet with DNS through the tunnel.
  - CI: build green (18 unit test suites); integration green in both DNS modes, 172 passed and 1 skipped, `test_97` included.
