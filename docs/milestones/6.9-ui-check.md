# 6.9 UI check

**Stage:** 6 · **Duration:** 1 d · **Depends on:** 6.8 · **Needed for:** 7.1

## Goal
Verify the finished UI as a whole before release: plasma-nm's stock “Import VPN connection” and “Export”, which load all VPN plugins, are not affected by ours, and the manual UI checklist (including the kill switch banner) passes. The stage 6 result then goes to documentation (7.1) and acceptance (7.2).

## Inputs
- The 6.3–6.5 editors with the 6.2 banner, import (6.7) and export (6.8); the three core packages installed in the VM.
- [design.md](../design.md), section “plasma-nm user interface”: no support for the stock import and export (`supportedFileExtensions()` is empty, `suggestedFileName()` is empty); item “Who loads the plugin”.
- [design.md](../design.md), section “Leak protection”: item “How the user learns about a block”, `--clear <uuid>` and bare `--clear`, the kill switch only for default-route tunnels.
- [design.md](../design.md), section “Testing”: the UI is tested manually against a checklist.
- The code of the stock import and export in plasma-nm 6.7.4, `kcms/kcm_connections/kcm.cpp`: `importVpn`, `importVpnFile`, and `onRequestExportConnection`, which loads the plugin via `VpnUiPlugin::loadPluginForType` and returns with only a log warning when `suggestedFileName()` is empty.

## Tasks
- [ ] Check plasma-nm's stock “Import VPN connection” in the VM with the three packages installed:
  - loading our plugins has no side effects: no D-Bus calls, files, dialogs or log messages;
  - importing `.ovpn` and a WireGuard `.conf` works the same as without our packages;
  - an AmneziaWG `.conf` imported through the stock import does not create a profile of our type; record what happens instead, for the README (7.1).
- [ ] The stock “Export” in the connection menu for our profile → does nothing and does not crash (the `onRequestExportConnection` path above). Record this for the README.
- [ ] A manual UI checklist in the repository (next to the tests):
  - the “Add VPN” list for the three protocols, field validation and error messages (rendered strings, never raw message codes);
  - the three secret storage modes, the default storage (StoreForUser when a keychain is available) and “Not required” for optional secrets; every secret field and `uuid` masked; the VLESS `encryption` field (default `none`); the secret prompt from the applet (kded6 with our `askUser()` widget);
  - import by pasting and from a file, warnings, confirmation before replacing fields, the paste field cleared after a successful import; export with and without secrets;
  - editing and re-saving a profile: `setPersistent(true)` is written on every save, so `vpn.persistent=yes` holds for a new profile and after re-saving an existing one;
  - the kill switch hint shown next to the checkbox in all three editors; in the AmneziaWG editor the checkbox disabled when `allowed-ips` has no `0.0.0.0/0`;
  - the “Kill switch block active” banner: shown with a block (listing all blocked profiles by name), hidden without; “Clear” asks for administrator credentials, removes the block, the banner disappears; “Clear all” skips a profile that is activating; refusing authentication changes nothing;
  - keyboard navigation; all strings go through ki18n.
- [ ] Run through the checklist in the VM; fix the bugs found or file issues for them.

## Deliverables
- The UI checklist file, marked as passed.
- Notes for the README (7.1) about the stock import and export.

## Done when
- [ ] Stock “Import VPN connection” with `.ovpn` and a WireGuard `.conf` in the VM → works; no messages from our plugins in the log.
- [ ] Stock “Export” on one of our profiles → no dialog, no crash.
- [ ] UI checklist → passed, marked in the file; re-saving an existing profile of each protocol keeps `vpn.persistent=yes`.

## Risks and notes
- That `.conf` files go to WireGuard and OpenVPN, and that the stock import works only with files, is already established in design.md and is not rechecked.
- Bugs that do not fit into the day are filed as issues and fixed before 7.2.
