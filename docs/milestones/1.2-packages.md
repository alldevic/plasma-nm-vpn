# 1.2 Packages

**Stage:** 1 · **Duration:** 2 d · **Depends on:** 1.1 · **Needed for:** 1.3, 1.4

## Goal
Get the full set of .deb packages out of CI, with correct dependencies and with cores verified against pinned hashes. This removes the risk that packaging issues (the private plasma-nm library, versions that include the core version, building cores from tags) only surface right before the release.

## Inputs
- The skeleton and `build.yml` from 1.1; the empty daemon and editor.
- [design.md](../design.md), section “Packages”: the table of packages and dependencies (`pkexec` for `plasma-nm-vpn-common`), paragraph “Removal and upgrades” (the `prerm` scripts), `plasma-nm (>= 4:6.0), plasma-nm (<< 4:7)`, the explicit `libqt6core6t64` dependency (item “plasma-nm compatibility”), package versions, the `plasma-nm-vpn` user on purge, the path `/usr/lib/plasma-nm-vpn/bin/`, where the cores come from (amneziawg-go `v3.1.20261116`, amneziawg-tools `v3.1.20260812`).
- [design.md](../design.md), section “plasma-nm user interface”, item “Packaging” (shlibs).
- [design.md](../design.md), section “Distribution and supply chain”, items “Cores” and “Core licenses”.
- [design.md](../design.md), section “Architecture”, items “amneziawg-go” (`/run/amneziawg` via tmpfiles.d) and “Paths” (`/usr/share/plasma-nm-vpn/` for templates and allowlists).

## Tasks
- [x] Core pins as data: one file per core in `cores/` (for example, `cores/sing-box.env`: version, archive name, sha256; for cores built from source, the tag and commit hash). Changes to these files are reviewed like code.
- [x] Download script for sing-box and xray: download `sing-box-<version>-linux-amd64.tar.gz` and `Xray-linux-64.zip`; check the sha256 against `cores/`; additionally check against upstream — the `.dgst` file for xray, the asset's `digest` field from the GitHub API for sing-box. Any mismatch fails the build. Only the binary and LICENSE are taken from the archives.
- [x] Build amneziawg-go and `awg` from tags: `git clone --branch <tag>`, check `git rev-parse HEAD` against the hash in `cores/`, build with the upstream Makefile (amneziawg-go with Go in CI; `awg` in a forky container). `awg-quick` is not shipped in the package.
- [x] `debian/control` (a single source package): `plasma-nm-vpn-common`, `plasma-nm-vpn-sb`, `plasma-nm-vpn-xray`, `plasma-nm-vpn-amneziawg`, the `plasma-nm-vpn` metapackage, `plasma-nm-vpn-archive-keyring` (`Architecture: all`). Dependencies per the design.md table (`plasma-nm-vpn-common` — `network-manager`, `nftables`, `pkexec`). The list of protocols goes into each core package's description. The sing-box package name may change in 7.1 (a neutral name if permission is not granted), so it is defined in one place (`debian/control`), and the scripts take the package list from there.
- [x] Versions per design.md: `0.1.0+sb1.14.4`, `0.1.0+xray26.11.9`, `0.1.0+awg3.1.20261116` (from the amneziawg-go tag; the `awg` version goes into the changelog); common, the metapackage and keyring get just the project version. The suffixes are computed from `cores/` and set via `dh_gencontrol -p<package> -- -v<version>` (verify that this works with a single source package). Core packages depend on `plasma-nm-vpn-common (= <project version>)`, since the library is private; `${binary:Version}` does not fit (the core package version carries the core suffix), so `debian/rules` passes the project version as its own substvar.
- [x] shlibs: `override_dh_shlibdeps` passing `--ignore-missing-info` to `dpkg-shlibdeps`; `plasma-nm (>= 4:6.0), plasma-nm (<< 4:7)` added to `Depends` by hand.
- [x] Qt: `dpkg-shlibdeps` derives the Qt version from the symbols used and would allow an older Qt that rejects the plugin. `debian/rules` computes the Qt version used for the build (for example, from `dpkg-query -W -f='${Version}' libqt6core6t64`, upstream part only — check which form Qt compares) and passes it as a substvar (`-Vqt:BuildVersion=…`); packages with editors get `libqt6core6t64 (>= ${qt:BuildVersion})` in `Depends`.
- [x] The `/usr/share/plasma-nm-vpn/` directory in the packages (empty for now: templates and allowlists arrive in 2.2–2.6, 3.1, 4.1). The `plasma-nm-vpn` user via sysusers.d in `plasma-nm-vpn-common` (like `nm-openvpn-sysusers.conf` in NetworkManager-openvpn), `/run/amneziawg` owned by `plasma-nm-vpn` via tmpfiles.d in `plasma-nm-vpn-amneziawg`; verify support for `dh_installsysusers`/`dh_installtmpfiles` in forky's debhelper.
- [x] Maintainer scripts (design.md, paragraph “Removal and upgrades”), only on `remove` (not on `upgrade`: an upgrade does not touch running connections):
  - `prerm` of each core package deactivates the active VPN connections of that package's service types (`nmcli -g UUID,TYPE connection show --active`, then the service type of each VPN; `nmcli connection down`), so that its daemons clean up after themselves, and then waits, with a bound (chosen here, for example 20 s), until the `plasma-nm-vpn-daemon-<uuid>.scope` of each of those connections is gone; on timeout it prints a warning and continues, so that the removal is not blocked;
  - `prerm` of `plasma-nm-vpn-common` removes all our nftables chains (`nft delete table inet plasma_nm_vpn` if it exists) and `/run/plasma-nm-vpn/guard-status`, so that no block is left without a tool to clear it.
  Both scripts succeed when there is nothing to do (no NM running, no table, no file).
- [x] `plasma-nm-vpn-archive-keyring`: with a test key for now; the file `/etc/apt/sources.list.d/plasma-nm-vpn.sources` with `Signed-By`, the URI built from the repository name (`GITHUB_REPOSITORY`) so that the 1.3 test runs against the test repository.
- [x] `debian/copyright` (DEP-5): the project's MIT, LGPL for the vendored headers, core licenses per the design.md table, including the verbatim additional term of sing-box.
- [x] A `packages` CI job (in a forky container): `dpkg-buildpackage -b`, `lintian` in warning mode, the .deb files as workflow artifacts.

## Deliverables
- `debian/`, `cores/`, core download and build scripts, the `packages` job.

## Done when
- [x] Run the `packages` job → six .deb files in the artifacts; `dpkg-deb -I` shows versions that include the core version for core packages and the expected `Depends`.
- [x] Replace a sha256 in `cores/` with a wrong one → the build fails at the check.
- [x] In the VM (snapshot from 0.2): `apt install ./*.deb` → installs without dependencies beyond our packages, except `pkexec` if 0.2 found it absent from a stock installation; the `plasma-nm-vpn` user and `/run/amneziawg` exist, `/usr/lib/plasma-nm-vpn/bin/` contains sing-box, xray, amneziawg-go, awg.
- [x] `apt purge` of all packages → the system's file list before installation and after removal match (compare `find / -xdev` against the snapshot), except for the `plasma-nm-vpn` system user, which stays, as is customary in Debian. Excluded from the comparison: dpkg and apt state (`/var/lib/dpkg/`, `/var/lib/apt/`, `/var/cache/apt/`), logs (`/var/log/`), other caches (`/var/cache/`), the `/etc/{passwd,group,shadow,gshadow}-` backups, and `pkexec` with its dependencies if it was pulled in. `find -xdev` does not descend into `/run` (tmpfs), so check explicitly: `/run/amneziawg` and `/run/plasma-nm-vpn/` do not exist.
- [x] `dpkg-deb -f <editor package>.deb Depends` contains `libqt6core6t64 (>= <the Qt version from the build container>)`, and every core package's `Depends` contains `plasma-nm-vpn-common (= 0.1.0)` (the project version, without a core suffix).
- [x] Create a test chain in `inet plasma_nm_vpn` and a `/run/plasma-nm-vpn/guard-status` file by hand → `apt remove plasma-nm-vpn-common` (and with it the core packages) → no table, no file. Reinstall, create the chain again and upgrade to a rebuilt package with a higher version → the chain survives (`prerm upgrade` does nothing). The core `prerm` with an active connection (deactivation and the bounded wait for the scopes) is tested end to end in 2.7.

## Risks and notes
- `/run/amneziawg` from tmpfiles.d remains after package removal until reboot (it is tmpfs); if the explicit check finds it, remove the directory in `postrm` on purge. The same applies to `/run/plasma-nm-vpn/`, which gets its own tmpfiles.d line in `plasma-nm-vpn-common` in 2.3.
- GitHub may rename assets containing `+`; this is handled at publication (1.3); here the .deb names are standard.
- That there are no dependencies beyond a standard KDE installation (nftables, json-glib) has already been verified in design.md.
- Results: CI job `packages` (run on `6ec54b5`) builds the six packages in `debian:forky`, lintian clean with commented overrides (static Go binaries, the upstream sing-box without PIE/RELRO, the keyring's apt source). `dh_gencontrol -p<pkg> -- -v<version>` works with one source package; the Qt substvar is the upstream part of `libqt6core6t64`'s version (`6.11.2`). In the clean VM: install brings only `pkexec`; upgrade to a rebuilt 0.1.1 keeps a test chain and `guard-status`; `apt remove plasma-nm-vpn-common` removes both; after purge the file list matches the snapshot (the only differences are `libnetplan1`, auto-removed by the test, and a `systemd-private-*-upower` directory, neither ours), `/run/amneziawg` and `/run/plasma-nm-vpn` are gone, the user stays. A wrong sha256 or commit in `cores/` fails `fetch-cores`. The upstream release binaries are not stripped; amneziawg-go and `awg`, built here, are. `postrm` on purge also removes `/run/plasma-nm-vpn` (created from 2.3 on).
