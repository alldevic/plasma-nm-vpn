# 0.1 sing-box question

**Stage:** 0 · **Duration:** 0.5 d · **Depends on:** — · **Needed for:** 7.1

## Goal
Ask the sing-box authors in advance whether the additional term in their license permits the package name `plasma-nm-vpn-sing-box`. The answer may take a long time, so the question is asked at the very start and we wait for it while the rest of the work goes on. The answer is needed at the start of milestone 7.1, where the package name is settled so that the README and acceptance already use it.

## Inputs
- [design.md](../design.md), section “Distribution and supply chain”, item “Core licenses”: sing-box is GPL-3.0-or-later with the term “In addition, no derivative work may use the name or imply association with this application without prior consent”; with no permission or no answer by the start of 7.1, the package ships under a neutral name chosen in 7.1.
- [design.md](../design.md), section “Open questions and risks”, list “Before the first publication”.
- What the question is about: only the package name `plasma-nm-vpn-sing-box`. What stays in any case (design.md, item “Core licenses”) and is not asked about: the `+sb` version suffix (an abbreviation, not the name), the upstream names of the core binary and the GPL source archive, and naming the core in the package description and the license information. System identifiers do not contain the name at all: NM services are named after protocols (`org.freedesktop.NetworkManager.pnv.hysteria2` and so on), and the core unit is `plasma-nm-vpn-core-<uuid>.service`.

## Tasks
- [ ] Read CONTRIBUTING and the issue templates in the SagerNet/sing-box repository: do they accept license questions as issues, or is another channel designated for that (Discussions, email)? Ask the question where they ask for it to be asked.
- [ ] Write the text in English, short and to the point:
  - what the project is: open-source NetworkManager and KDE plasma-nm plugins, installed from the project's own apt repository;
  - how sing-box is used: the unmodified binary from the upstream release is repackaged into a `.deb`, the sources of the same version are published alongside it (GPL), and the license and a link to upstream are provided; the description says only that the package includes sing-box, with no implied association with the project;
  - one direct question: may the package be named `plasma-nm-vpn-sing-box`; if not, which package name the authors would consider acceptable.
- [ ] Sketch 1–2 neutral package names without “sing-box” and offer them in the issue as an alternative; the final choice is made at the start of 7.1.
- [ ] Create the issue (or a message in the designated channel) from the account that will run the project.
- [ ] Set a reminder to check for an answer once a week.
- [ ] Update design.md: in “Open questions and risks”, list “Before the first publication”, add the issue link and the date; the item stays open until there is an answer.

## Deliverables
- An issue (or discussion) in the sing-box channel, with a link.
- The link and date in design.md; the neutral name options are in the issue text.

## Done when
- [ ] Open the link from design.md → the issue exists and asks one direct question about the package name `plasma-nm-vpn-sing-box`.
- [ ] A task to check for the answer is scheduled before the start of 7.1.

## Risks and notes
- The issue may be closed without an answer or as “not a bug”. In that case, ask in another channel listed in the repository; silence does not count as consent: with no answer by the start of 7.1, the package ships under a neutral name (design.md, item “Core licenses”).
- If the answer is “no”, only our package name changes. NM services, units and user profiles are not affected. The rename is done at the start of 7.1, not earlier; 7.3 only publishes.
- The sing-box license (GPL-3.0-or-later with the name term) has already been checked against upstream in design.md; no need to recheck it.
