# 6.3 Hysteria2 editor

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 6.2, 5.8 · **Needed for:** 6.4, 6.5, 6.7

## Goal
The first real editor: a Hysteria2 profile is created in plasma-nm and connected from the applet, without `nmcli` or editing `.nmconnection`. The milestone exercises the whole chain “form → profile → secrets → daemon” and sets the pattern for 6.4 and 6.5.

## Inputs
- Shared blocks, the message code rendering and the metadata template from 6.1, the kill switch banner from 6.2. The Hysteria2 daemon, stable via `nmcli` (stages 2 and 5, concluding with 5.8). The integration bench from 1.4 with the port-hopping extension from 2.5; the bench DNS 203.0.113.1.
- [design.md](../design.md), section “plasma-nm user interface”:
  - item “Build”: vendored `vpnuiplugin.h`, `settingwidget.h`, `passwordfield.h` and our own `plasmanm_editor_export.h`; linking only against `libplasmanm_editor.so`, plus NetworkManagerQt, KF6CoreAddons, KF6WidgetsAddons, KF6I18n, Qt6 Widgets and the libnm headers;
  - `vpn.persistent=yes` via `VpnSetting::setPersistent` on every save; why the editor does not set `ipv4.*`;
  - form validation through the 2.2 library, allowlists included;
  - no support for plasma-nm's stock import and export; item “Who loads the plugin”.
- [design.md](../design.md), section “Profile data schema”: Hysteria2 keys, `ports` instead of `port`, item “Secrets”.
- [design.md](../design.md), section “Leak protection”, item “Kill switch”: the editor cannot see never-default and shows a permanent hint next to the checkbox; the daemon ignores the setting with never-default.
- [design.md](../design.md), section “Architecture”, item “Service names follow the protocol, not the core”: `org.freedesktop.NetworkManager.pnv.hysteria2`.
- Code samples in plasma-nm 6.7.4: `vpn/openvpn` (`setPasswordNotRequiredEnabled`), `vpn/sstp` (`sstpwidget.cpp`: `fillOnePasswordCombo`, `handleOnePasswordType`) and `libs/editor/settings/wireguard*`.

## Tasks
- [x] A `VpnUiPlugin` subclass in the `plasma-nm-vpn-sb` package:
  - `K_PLUGIN_CLASS_WITH_JSON`, `X-NetworkManager-Services` = `org.freedesktop.NetworkManager.pnv.hysteria2`, installed into `qt6/plugins/plasma/network/vpn/`;
  - `supportedFileExtensions()` returns an empty list, `suggestedFileName()` an empty string;
  - a constructor without side effects: no access to D-Bus, NM, files or the network, because plasma-nm's stock import also loads the plugin.
- [x] `widget()`: a `SettingWidget` built from the 6.1 blocks, a group of its own and the 6.2 banner at the top.
  - 6.1 blocks: “Server” in `ports` mode, “TLS” without fingerprint and with the pin field only if 2.5 found a sing-box equivalent of `pinSHA256` (otherwise hidden, design.md records the outcome), “Authentication”, “Protection” (with the 6.1 kill switch hint), “Advanced” with `mtu` and `extra` (Hysteria2 `extra` allowlist from the package data, 2.5).
  - Its own group “Obfuscation, port hopping”: `obfs` (`salamander` or empty), `hop-interval`, as well as `up-mbps` and `down-mbps`, checked by the 2.2 validators.
  - Call `watchChangedSetting()`, implement `isValid()`; validation messages are the codes rendered by 6.1.
- [x] The `password` and `obfs-password` secrets via `PasswordField` with `setPasswordModeEnabled(true)` (masked input, as for every secret field; design.md, “plasma-nm user interface”) and `setPasswordOptionsEnabled(true)`; for the optional `obfs-password` also `setPasswordNotRequiredEnabled(true)`.
  - Flags are written to `vpn.data` as `password-flags` and `obfs-password-flags`: StoreForUser → `AgentOwned`, StoreForAllUsers → `None`, AlwaysAsk → `NotSaved`, NotRequired → `NotRequired`. The default storage is the `PasswordField` default, not set by the editor: StoreForUser when a keychain is available (`QKeychain::isAvailable()`), otherwise the widget's own fallback. The only override: `obfs-password` with `obfs` empty gets NotRequired.
  - `loadSecrets()` fills the fields, and `setting()` puts the secrets into `vpn.secrets`, not into `vpn.data`.
- [x] `askUser()`: a widget that asks for missing secrets based on `hints`, for the “Ask for this password every time” mode and for a wrong password. kded6 loads it.
- [x] `setting()` writes the current-version `schema` and calls `VpnSetting::setPersistent(true)` on every save, new or existing profile: plasma-nm replaces the whole `vpn` setting with what the plugin returns. Verify that the value reaches the saved profile through `ConnectionSettings::fromMap()` in `ConnectionEditorBase::setting()`.
- [x] Strings via ki18n, source strings in English; `Name[ru]` and `Description[ru]` are passed to the 6.1 CMake function (placeholders until 7.1).

## Done when
- [x] The “Add VPN” list in the VM → a Hysteria2 entry is present, the form opens.
- [x] A profile created in the form against the bench from 1.4 with the port-hopping extension from 2.5 (single port and `443,20000-20100` with Salamander), DNS 203.0.113.1 set in the “Protection” block before connecting → connects and disconnects from the applet.
- [x] `nmcli -s -g vpn.data,vpn.secrets connection show <id>` → `password` and `obfs-password` are present only in `vpn.secrets`, the flags are set in `vpn.data`, and `ports` is written instead of `port`; both fields show their values masked in the form.
- [x] Each of the three secret storage modes → the connection succeeds; with “Ask for this password every time”, connecting from the applet makes kded6 show the password dialog with our `askUser()` widget. A profile without Salamander and `obfs-password` set to “Not required” → connects without a prompt.
- [x] `nmcli -g vpn.persistent connection show <id>` for a new profile → `yes`; re-saving an existing profile (any field changed) keeps `vpn.persistent=yes`.
- [x] An `extra` key outside the allowlist or a newline in `tls-sni` → the form is invalid, and the message is a readable string.
- [x] The “Protection” block → the hint “The kill switch applies only when all traffic goes through the VPN” is shown next to the kill switch checkbox.
- [x] A kill switch block produced by `kill -9` of the daemon after success, or by stopping the bench server and waiting for the cycle timeout → the 6.2 banner is visible in the Hysteria2 form.

## Risks and notes
- If `persistent` gets lost on the way through `ConnectionSettings::fromMap()`, raise the issue in design.md rather than working around it by calling plasma-nm's internal classes.
- The editor cannot see `ipv4.never-default` (the plugin gets only the `vpn` setting), so the checkbox stays enabled with the hint; with never-default the daemon ignores the kill switch and says so in the journal (design.md, “Leak protection”).
- `kill -9` of the core after success does not leave a block: the reconnect cycle restores the connection.
- How the daemon (2.1) treats a `NotRequired` empty secret in `need_secrets` is checked together with the “Not required” Done-when item.
- The editor does not touch `ipv4.dns-priority` and `ipv4.dns-search`: with a default-route tunnel, DNS is handled by NM (which adds `~.` itself) and by the nftables guard (design.md, section “DNS”).
- ABI compatibility of the headers and the need to restart the session after an update are already described in design.md (section “Packages”, item “plasma-nm compatibility”).
- Results:
  - **The editor.** `backends/sb/editor`: `Hysteria2Widget` (the 6.1 blocks, its own group “Obfuscation, port hopping”, the 6.2 banner), `Hysteria2AuthWidget` for kded6's prompt, and the plugin. The plugin does nothing until asked for a widget and declines import and export.
    - The groups sit in a `QScrollArea`. On the desktop, plasma-nm's dialog squeezed them over each other until then.
    - The pin field stays hidden (2.5). The `extra` allowlist is the package's `hysteria2-extra.list`; the form takes its path as a parameter for the tests.
    - `setting()` writes `schema=1` and `persistent=yes` on every save, the flags to `vpn.data` and the stored secrets to `vpn.secrets`.
    - Without obfuscation, `obfs-password` is always written as not required.
  - **Shared code for 6.4 and 6.5.** `common/editor/pnv-secrets.h` maps `PasswordField` options to secret flags and back: StoreForUser ↔ AgentOwned, StoreForAllUsers ↔ None, AlwaysAsk ↔ NotSaved, NotRequired ↔ NotRequired. Without flags, `PasswordField`'s own default stays: StoreForUser with a keychain, as the form showed in the VM. The module links `libpnv-widgets.so` with the RUNPATH `/usr/lib/<triplet>/plasma-nm-vpn` (`pnv_editor_install()`).
  - **Unit tests.** `tests/unit/editors/test_hysteria2_editor.cpp`, 9 QtTest cases offscreen: round trip of a full profile; a new profile is persistent with schema 1; the secret options and the not-required override; masked fields; readable messages for a newline in SNI and for `extra` outside the allowlist or with `detour`; the kill switch hint; the prompt with and without hints.
  - **Without a desktop.** `tests/integration/cases/test_94_hysteria2_editor.py`, through the new test-build driver `pnv-editor-form`. It loads the installed plugin as plasma-nm does, fills the fields and saves through `ConnectionSettings::fromMap`. Checked:
    - single port and `443,20000-20100` with Salamander connect;
    - `password`/`obfs-password` only in `[vpn-secrets]`, the flags and `ports` in `[vpn]`;
    - re-saving through the form (edit, with the secrets loaded from NM) brings back `persistent=yes` after it was set to `no`, and keeps the secrets;
    - “ask every time” fails without secrets and connects with `passwd-file`;
    - a profile without obfuscation, with `obfs-password` not required, connects without asking. The bench got a Hysteria2 inbound without obfuscation on UDP 4443.
    - An invalid field (newline in SNI, `extra` outside the allowlist, `detour`) saves nothing, with readable messages.
    - The banner shows in the form after `kill -9` of the daemon. The driver registers NM's D-Bus types itself: NetworkManagerQt does so only once something has asked it for its state.
  - **On the desktop (local VM, driven by QEMU input, screenshots).**
    - System Settings → “+” lists “Hysteria2 / Hysteria2 (plasma-nm-vpn)” among the VPN types, and the form opens with the tab “VPN (hysteria2)”. Save is disabled while the server is empty, with “Server: required” under the block, and the kill switch hint is shown.
    - Three profiles with `443,20000-20100` and Salamander, one per storage mode, each connected from the applet with traffic through the tunnel:
      - all users: connects directly;
      - ask every time: kded6 opens our prompt with “Password” and “Obfuscation password”, and the session succeeds;
      - this user only: the passwords typed in the editor and applied go to KWallet (not to the system profile), and the applet connects without a prompt.
    - Found: plasma-nm does not keep a secret typed at the connect prompt in the keychain, even for “this user only”: the next connect asks again. The keychain gets it when it is entered in the editor (design.md, “Editors”).
    - Editing works only from a process of the active desktop session: `kcmshell6` started over ssh gets “Insufficient privileges” from NM on save.
