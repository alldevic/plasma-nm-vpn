# 5.8 Network change and sleep tests

**Stage:** 5 · **Duration:** 2 d · **Depends on:** 5.7 · **Needed for:** 6.3

## Goal
Lock down reconnection in CI on a bench with two parent devices: a parent device change, a real s2idle suspend and a core crash after success all end in a recovered tunnel without leaks, with or without the kill switch. Fix the acceptable recovery time, which the MVP acceptance criteria leave to the results of this milestone.

## Inputs
- The reconnect cycle, its timeout, the core recreation on the persistent TUN (or the fallback block chain) and the test-build switches (skip step 1, change the DNS list in the cycle), from 5.5; the suites and shared helpers from 5.6 and 5.7; the test image with `mac80211_hwsim`, `hostapd` and s2idle suspend woken by `rtcwake` from 0.2 and 1.4; the bench from 0.3 with the bench DNS 203.0.113.1.
- [design.md](../design.md), sections “Network changes and sleep”, “Core supervision and cleanup” (item “Core unit failure”), “Leak protection”, “Testing” (VM over `AF_VSOCK`; sleep and Wi-Fi tests only under KVM), “MVP acceptance criteria”.

## Tasks
- [ ] Bench: the client VM gets two parent devices towards the server bench: emulated Wi-Fi (`mac80211_hwsim`, with the access point via `hostapd` on the bench side) and wired (the veth from 0.3, explicitly put under NM management, otherwise it will not become the VPN's parent device). Both have a route to the server; `tcpdump` on both for the duration of each test. The management NIC is never disconnected; with never-default it never becomes the VPN's parent device, and the VM is driven over `AF_VSOCK`.
- [ ] The sleep and Wi-Fi tests run only in the KVM variant of the bench and are skipped, with a visible reason, in the container fallback (they depend on the VM's own kernel).
- [ ] Test profiles set `dns=203.0.113.1` before connecting (the 0.3 rule: 9.9.9.9 is unreachable on the bench, 1.1.1.1 is reserved for the never-default check); secrets via `nmcli connection up … passwd-file`; DNS in both modes (default `resolv.conf` and systemd-resolved). The tests below run with `kill-switch=yes` unless stated otherwise.
- [ ] “Parent device change”: tunnel up on veth → `nmcli device disconnect` of it → the connection goes ACTIVATING → ACTIVATED, the route to the external gateway is on Wi-Fi, the liveness check passes, traffic and DNS go through the tunnel; then back. The captures have no DNS or IPv6 bypassing the tunnel and no traffic bypassing it except the kill switch exemptions.
- [ ] “No leak without the kill switch”: the same device change and a `kill -9` of the core with `kill-switch=no` on a default-route tunnel, under a continuous `curl` to the bench and a `dig` loop → no IPv4 leaves directly during the cycle (only the core's traffic to the server, DHCP and local networks), because the persistent TUN keeps NM's routes, or, for a core using the fallback, because the temporary block chain is in place during the restart.
- [ ] “Device comes back later”: both devices disconnected, one reconnected well within the cycle timeout → the connection recovers; none reconnected → give-up after the timeout, the kill switch chains and the `guard-status` entry remain.
- [ ] “Sleep”: `rtcwake -m no -s <N> && systemctl suspend` in s2idle with the tunnel up, so that logind itself emits `PrepareForSleep`; NM takes the devices down on suspend and brings them back after resume → the tunnel is restored without user involvement and without leaks. The test waits for the VM to resume over vsock rather than treating it as dead. Suspend on real hardware is checked on the hardware test machine in 7.2, if it is available.
- [ ] “Core crash after success”: `kill -9` of the core under load (e.g. a continuous `curl` to the bench) → no direct traffic in the captures, the connection is ACTIVATED again with the liveness check passed, no `guard-status` entry; for AmneziaWG the stale socket was removed, `awg setconf` has run again and the handshake is fresh. Repeated kills → the increasing backoff is visible in the journal.
- [ ] Tests are parameterized by protocol (Hysteria2, AmneziaWG, VLESS XHTTP Reality) where this does not require separate code.
- [ ] Recovery time: measure it in the device change, sleep and core crash tests over several runs each, choose an acceptable value with a margin, check it in the tests and record it in design.md, section “MVP acceptance criteria”.

## Deliverables
- A network change and sleep integration test suite in CI.
- The acceptable recovery time in design.md, section “MVP acceptance criteria”.

## Done when
- [ ] The suite in CI on a pull request → green for all three protocols and both DNS modes (sleep and Wi-Fi tests in the KVM variant).
- [ ] The test build with step 1 skipped (no `STARTING`) and its second switch sending a different DNS list in the cycle's `Ip4Config` → the DNS check after a device change (which looks for the new list) fails, in both DNS modes; with the DNS-list switch alone, the same check passes. The second switch is required: with the same DNS list, the configuration left from before the cycle would make the check pass even without step 1, so the test would pass vacuously.
- [ ] A local patch that drops the persistent TUN (the core creates its own TUN on restart, without the fallback chain), checked once by hand → the “no leak without the kill switch” test fails.
- [ ] design.md, “MVP acceptance criteria”, states a specific recovery time, and the tests check it.

## Risks and notes
- Timing-based tests are flaky on shared runners: take the threshold with a margin rather than from the median, and log the actual time.
- If s2idle does not work under the CI runner's KVM even though it did in 0.2, the sleep test is skipped there with the reason logged and runs in the local VM and on the hardware test machine in 7.2; no emulated sleep path is added to the daemon.
- Wi-Fi emulation tests the device change, not the behaviour of a real radio; real Wi-Fi is tested on the hardware test machine in 7.2, if it is available.
