# 1.5 Upstream watch

**Stage:** 1 · **Duration:** 1 d · **Depends on:** 1.1 · **Needed for:** —

## Goal
Learn about changes to the plasma-nm headers in sid and about new core versions automatically, not from users. This is the main mitigation of the residual risk of the internal `VpnUiPlugin` API: a fix must ship within the ~5 days it takes plasma-nm to migrate from sid to forky.

## Inputs
- The vendored headers and `third_party/plasma-nm/VERSION` from 1.1; core pins in `cores/` from 1.2 (if 1.2 is not finished yet, a temporary list of current versions).
- [design.md](../design.md), section “Packages”, items “plasma-nm compatibility” and “Core updates”.
- [design.md](../design.md), section “Open questions and risks”, risks “The `VpnUiPlugin` API is internal” and “sing-box is moving away from running without root”.

## Tasks
- [ ] The `upstream-watch.yml` workflow: `schedule` (once a day) and `workflow_dispatch`; permissions `contents: read`, `issues: write`; actions pinned by SHA.
- [ ] plasma-nm headers: in a `debian:sid` container with `deb-src` enabled, run `apt-get source plasma-nm` (with Debian patches applied), take `libs/editor/vpnuiplugin.h`, `libs/editor/widgets/settingwidget.h`, `libs/editor/widgets/passwordfield.h` and compare them with `third_party/plasma-nm/` using `diff -u`. Record the plasma-nm versions in sid and forky in the job report.
- [ ] Cores: the latest stable version (no pre-releases) via the GitHub API — releases of `SagerNet/sing-box` and `XTLS/Xray-core`, tags of `amnezia-vpn/amneziawg-go` and `amnezia-vpn/amneziawg-tools`; compare with `cores/`. Verify the repository owners against the links in `cores/`.
- [ ] Create an issue via `gh issue create` with the labels `upstream` and `plasma-nm` or `core`: the body contains the version, a link to the release or changelog, and for headers the `diff`. Before creating, search for an open issue with the same title (`gh issue list --search "in:title …"`) so as not to create duplicates every day.
- [ ] For a new sing-box version, add to the issue body a reminder to check whether running without root is still supported in the release (see the risk in design.md).
- [ ] Errors of the job itself (API unavailable, `apt-get source` failed) produce a red run, not a silent skip.

## Deliverables
- `.github/workflows/upstream-watch.yml` and a comparison script (for example, `ci/upstream-watch.sh`).

## Done when
- [ ] Temporarily change a line in a vendored header on a branch and run the job manually → an issue with the `diff` is created.
- [ ] Temporarily lower the xray version in `cores/` → an issue about a new xray version is created; a repeated run does not create a new issue.
- [ ] Run on current data → no issues, the run is green.

## Risks and notes
- The diff also catches edits that do not change the ABI (like the clang-format reformatting in the 6.x series): a human decides from the issue whether to rebuild. The absence of ABI changes in 6.0.0–6.8.3 has already been verified in design.md.
- The check is limited to three headers: it does not catch Qt incompatibilities; the forky build catches those.
- The job runs in CI and adds no network requests on users' machines.
