# 5.7 Block and connection tests

**Stage:** 5 · **Duration:** 2 d · **Depends on:** 5.6 · **Needed for:** 5.8

## Goal
Lock down in CI everything around a block that 5.6 does not cover: the inherited block, re-activation (takeover), block status and clearing, liveness detection, and two simultaneous connections that must not break each other's tunnels or DNS.

## Inputs
- The inherited path, the cache rules for inherited attempts and re-activation detection from 5.2, as found in 0.7 (which re-activation signal arrives in time); `guard-status` and `plasma-nm-vpn-guard --clear [<uuid>]` with polkit from 5.3; the liveness check and its timeout from 5.4; the reconnect cycle and its timeout from 5.5; the test setup, helpers and bench additions from 5.6; the test-build hook that holds the daemon before `Ip4Config` from 2.7.
- [design.md](../design.md), section “Leak protection” (items “Re-activation”, “Inherited block”, `plasma-nm-vpn-guard --clear`, “How the user learns about a block”), sections “Route to the server”, “DNS”, “Core supervision and cleanup” (item “Liveness check”), “Testing”.

## Tasks
- [x] “Inherited block survives”: a block from a successful session (`kill -9` of the daemon), then an attempt with the bench server stopped → no second set of kill switch chains during the attempt, no DNS query bypassing the tunnel, it uses the cached server IP, fails the liveness check, the chains and the entry stay; an attempt held by the hook and ended with `nmcli connection down` → they stay too; the cache file deleted → `nmcli connection up` fails at once and they stay; the server back up → a successful connect swaps the chains in one transaction and the entry is gone; the profile switched to `kill-switch=no` → a successful connect removes them.
- [x] “Re-activation”: after success, `nmcli connection up` of the same profile while it is up → the kill switch chains are present at every sample during the switch, no sample during the switch or 30 s after it shows a visible block (a `blocked` entry, or a `handing-over` entry older than 30 s: the 6.2 banner rule), the `handing-over` entry is gone after adoption, the new session succeeds and owns them, no inherited marker remains; the journal names the re-activation signal recorded in 0.7. With the bench server stopped before re-activating → the new attempt fails its liveness check, the chains stay and the entry appears. A session held by the hook (not succeeded; the hook does not block the daemon's main loop, so the held instance still handles `Disconnect`), re-activated → its chains are removed, the new attempt starts with its own, and a failure of it leaves no chains.
- [x] “Server IP changed”: a block from a successful session; the bench server moves to a new address and the “ISP” DNS record follows → the attempt uses the cached server IP and fails the liveness check, the block stays. `plasma-nm-vpn-guard --clear <uuid>` as a regular user → the polkit prompt (answered via `pkttyagent`) → chains and entry are gone; the next connect resolves the new address, succeeds and updates the cache.
- [x] “Bare `--clear`”: a third profile with the kill switch is connected first (or uses an IP literal in `server` or a cached server IP, since the blocks stop name resolution), then two other profiles are blocked → both blocks are cleared, the third connection's chains stay. `--clear` refused at the polkit prompt → nothing changes, non-zero exit code.
- [x] “Liveness detection”: a wrong password (Hysteria2), a wrong `uuid` (VLESS), a wrong key (AmneziaWG) and a dead server, with the kill switch → ACTIVATED, then give-up within the check timeout; no kill switch chains, no `guard-status` entry, no cache written, direct traffic flows. A working connection, then the bench server is stopped → the periodic check starts the reconnect cycle, which gives up after the cycle timeout; NM does not reconnect, the chains are in place, `guard-status` shows the block. The detection time is logged (about three minutes for the proxy cores, the 5.4 bound of about five to six for AmneziaWG).
- [x] “Two simultaneous connections”: a default-route profile with the kill switch and a never-default profile with `kill-switch=yes` (ignored: no kill switch chains) and a route to a bench address → traffic and DNS routed into either tunnel pass; one is disconnected → the other keeps working and keeps its chains.
- [x] “1.1.1.1 is not taken over”: a never-default profile without `dns` and a default-route profile with empty `dns` up at the same time → the default-route profile's DNS queries to 1.1.1.1 go into its own tunnel (none on the never-default TUN except the liveness check's), no route to 1.1.1.1 via the never-default TUN, 1.1.1.1 is not added to the system DNS by the never-default profile, both liveness checks pass.
- [x] Tests are parameterized by protocol (Hysteria2, AmneziaWG, VLESS XHTTP Reality) where this does not require separate code; DNS in both modes.

## Deliverables
- A block, clearing, liveness and multi-connection integration test suite in CI.

## Done when
- [x] The suite in CI on a pull request → green for all three protocols and both DNS modes, together with the 5.6 suite.
- [x] Ignoring the inherited marker → the “inherited block survives” test fails; ignoring both re-activation signals → the re-activation test fails; honouring a re-activation without the success marker → the never-succeeded re-activation case fails; a takeover that writes a `blocked` entry or leaves the `handing-over` entry in place → the re-activation test fails.
- [x] A removed `pnv-*` exemption → the two-connection test fails; a route to 1.1.1.1 via the TUN for the never-default check → the “1.1.1.1 is not taken over” test fails; a liveness check that always passes → the liveness detection test fails.

## Risks and notes
- The stopped-server tests last three periodic checks plus the cycle timeout; keep them to one protocol per run if CI time becomes a problem, and log the actual times rather than asserting tight bounds.
- The deliberately broken variants in “Done when” are checked once by hand with a local patch, not with switches in the daemon; the only test hooks live in the never-packaged test build.
- What NM does on re-activation was recorded in 0.7; if NM's behaviour differs from that record, fix the record before changing the daemon.
- Results:
  - The suite: `tests/integration/cases/test_70_blocks.py`, 15 cases on the 5.6 helpers. “Server stopped” is a drop rule for the server ports in netns `stand`. Cases:
    - **Inherited block survives** (three protocols): samples of `nft list` during the attempt always see one set of chains; no DNS query leaves `stand-cli`; Hysteria2 uses the cached IP; the attempt fails the liveness check, and the chains and entry stay. A held attempt ended with `down` keeps them too. Without a cache file, Hysteria2 fails at once and the block stays; the VLESS and AmneziaWG bench profiles use an IP literal and need no cache.
    - **Quick down and up**: replaces the re-activation case, which the 5.2 decision voids. `up` of the active profile is refused (“already active”); `down`, then `up` gives a new session with chains of its own, and no `guard-status` entry appears at any of the 100 samples.
    - **Server IP changed**: the old address is dropped, the new one 198.51.100.2 is a DNAT to the same server, and the name follows through `/etc/hosts`. The attempt under the block uses the cached old IP and fails; `--clear` as a regular user, with a temporary polkit rule as the consent, removes the block; the next connect resolves the new address, succeeds and caches it.
    - **Bare `--clear`**: with a third profile up, it clears the other two blocks; refused by polkit, it exits non-zero and changes nothing.
    - **Liveness detection** (three protocols): a wrong secret and a dead server give ACTIVATED, then a give-up within 40 s; no chains, entry or cache; direct traffic flows.
    - **Dead server after success**: the periodic checks start the cycle, which gives up after 120 s; the block stays; NM does not reconnect.
    - **Two connections**: a default-route profile with the kill switch and a never-default one, whose `kill-switch=yes` is ignored: traffic and DNS pass in either tunnel; one goes down, the other keeps working and keeps its chains.
    - **1.1.1.1 not taken over**: a never-default profile without `dns` and a default-route one with empty `dns`. There is no route to 1.1.1.1 via the never-default TUN and no DNS on it; queries for names go into the default-route tunnel, and only liveness queries appear on the never-default TUN.
  - Deliberate breakages, each failing its case:
    - the inherited path skipped → “inherited block survives”;
    - the `pnv-*` exemption removed from the kill switch → “two connections”;
    - a /32 to 1.1.1.1 via the never-default TUN → “1.1.1.1 not taken over”, failing on that route;
    - a liveness check that always passes → “liveness detection”.
    - The re-activation breakages are void with the hand-over (decided before 5.2).
