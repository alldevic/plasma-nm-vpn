# 6.8 Export

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 6.7 · **Needed for:** 6.9

## Goal
Complete profile transfer between machines: the “Export” button in our editor exports a profile to the same formats as import, and secrets go into the export only when explicitly chosen.

## Inputs
- The 6.3–6.5 editors with the import widget from 6.7; the 6.6 parsers (for the round trip).
- [design.md](../design.md), section “plasma-nm user interface”: the “Export” button, the same formats, a warning about losses; the stock import and export are not supported (`supportedFileExtensions()` is empty, `suggestedFileName()` is empty).
- [design.md](../design.md), section “Profile data schema”, item “Secrets”: export includes secrets only when explicitly chosen.

## Tasks
- [ ] Export generators next to the 6.6 parsers, with no dependency on widgets:
  - `hysteria2://` with `ports` as is;
  - `vless://` with the same parameters that import parses, including `encryption` as stored (`none` or the ML-KEM value);
  - AmneziaWG `.conf` without wg-quick keys; an empty `dns` produces no `DNS` line.

  Fields the format does not carry (for example, `kill-switch`, `allow-lan`, `extra`) are collected into a list of message codes with parameters (the field name), as the 6.6 parsers report theirs. This milestone adds those codes to the shared C code list as an export group (next to the validator codes from 2.2 and the parser codes from 6.6), adds a ki18n entry (`i18nc` with the parameters) for each of them to the 6.1 rendering table, and extends the 6.1 coverage test to the export group; the editor shows the warning rendered through that table.
- [ ] An “Export” button in the three editors: copy the link to the clipboard or save it to a file.
  - The “Include secrets” checkbox is unchecked by default.
  - A file with secrets is created with permissions 0600.
  - If a secret is not loaded (“Ask for this password every time” mode), warn that it will not be in the export. A secret marked “Not required” and left empty is simply omitted.
- [ ] A round-trip unit test: for each format, parsing (6.6) the export result preserves all fields the format carries; with and without secrets.

## Deliverables
- Export generators and the “Export” button in the three editors.
- The export group of message codes in the shared code list, its rendering entries and the extended coverage test.
- Round-trip unit tests in CI.

## Done when
- [ ] Exporting a profile of each protocol → importing into a new profile preserves all fields the format carries; the lost fields are listed in the warning on export.
- [ ] A `vless://` link with an ML-KEM `encryption` value imported in the VLESS editor (6.7) and saved → `vpn.data` holds the value unchanged; export → the link carries the same `encryption`; re-import into a new profile → the same value again.
- [ ] Export without the “Include secrets” checkbox → the link or file contains no `password`, `obfs-password`, `uuid`, `private-key`, `preshared-key`, `HeaderProtectionKey`.
- [ ] Export to a file with the “Include secrets” checkbox → the file has mode 0600.
- [ ] Round-trip tests in CI → green.
- [ ] The 6.1 coverage test extended to the export group → green in CI; the export warning shows rendered strings, never raw codes.

## Risks and notes
- Exporting to a link loses fields by the nature of the format; design.md allows this.
- A link with secrets copied to the clipboard may end up in Klipper's clipboard history. Mention this next to the checkbox.
- plasma-nm's stock “Export” from the connection menu is not used for our profiles; that it declines cleanly is checked in 6.9.
