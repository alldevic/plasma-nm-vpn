# 1.1 Repository skeleton

**Stage:** 1 · **Duration:** 2 d · **Depends on:** 0.8 · **Needed for:** 1.2, 1.4, 1.5, 2.1, 6.1

## Goal
Set up the product repository in which the daemon (C) and the editor (C++/Qt) build in a forky environment from the very first PR, and CI follows the supply chain rules from the start. Everything that comes later (packages, test bench, library, widgets) is added to the ready structure rather than carried over from the prototypes.

## Inputs
- Findings of 0.8: how the editor is built outside the plasma-nm tree against the headers from tag v6.7.4. The prototype code is not carried over; the decisions are.
- [design.md](../design.md), section “Architecture”: daemon language (C, libnm), UI plugin (C++/Qt 6, KF6).
- [design.md](../design.md), section “plasma-nm user interface”, item “Build”: which headers are copied, our own `plasmanm_editor_export.h`, what the editor links against.
- [design.md](../design.md), section “Distribution and supply chain” (CI on GitHub Actions, MIT project license, `SECURITY.md`).

- [x] `third_party/plasma-nm/`: `vpnuiplugin.h`, `settingwidget.h`, `passwordfield.h` from tag v6.7.4 (`libs/editor/` and `libs/editor/widgets/`) with their license headers preserved and the LGPL text alongside; our own `plasmanm_editor_export.h` with the `PLASMANM_EDITOR_EXPORT` macro; a `VERSION` file with the tag the headers were vendored from (read by 1.5).

- [x] Empty daemon: `main()`, linked against libnm and against the empty library from `common/daemon/`. The service names are already defined in design.md (`org.freedesktop.NetworkManager.pnv.hysteria2` etc.), but the `.name` file, the D-Bus policy and the daemon's install path come in 2.1.

- [x] `LICENSE` (MIT); stub `README.md` (one page: purpose, status “in development”) and `SECURITY.md` (reports via private GitHub Security Advisories); enable private vulnerability reporting in the repository settings.
- [x] `.github/workflows/build.yml`: triggers `pull_request` (never `pull_request_target`) and `push` to `master`; a job in a `debian:forky` container, installing build dependencies (check the exact `-dev` package names in forky), `cmake -B build && cmake --build build && ctest --test-dir build`.
- [x] CI rules: all third-party actions pinned by commit SHA with a version comment; `permissions: contents: read` at the top level of the workflow; the triggers are `pull_request` (never `pull_request_target`) and `push` to `master`, and no build job gets secrets. Enable Dependabot for `github-actions` so SHAs are updated via reviewed PRs.

## Deliverables
- Directory layout, CMake, vendored headers with `VERSION`, `LICENSE`, stub `README.md` and `SECURITY.md`.
- The `build.yml` workflow, building everything in a forky container on every PR.

## Done when
- [x] Open a PR with an empty change → `build.yml` is green, both the daemon and the editor module are built.
- [x] Break compilation in a PR → the check is red and the PR cannot be merged (branch protection on `master` with a required check (the admin may bypass it: work goes directly to `master`) is enabled).
- [x] `grep -rE 'uses: [^@]+@' .github/workflows` → every action reference contains a 40-character SHA.
- [x] `nm -D` on the editor module shows unresolved `VpnUiPlugin` symbols, and `ldd` shows a dependency on `libplasmanm_editor.so` (linking only against it, as in design.md).

## Risks and notes
- The `VpnUiPlugin` API is internal; header compatibility across 6.0.0–6.8.3 has already been verified in design.md and does not need rechecking. Tracking changes is milestone 1.5.
- The real constraint is the Qt version: the build must run in a forky container, not on an Ubuntu runner.
- The vendored headers are LGPL while the project is MIT: this must be reflected in `debian/copyright` (1.2) and the README.
- The models for building the module are `vpn/sstp` and `vpn/openvpn` in the plasma-nm sources (the WireGuard editor lives in `libs/editor/settings/wireguard*` and is not a model for CMake).
- Results: the skeleton builds in `debian:forky` on GitHub Actions (run on `5d6bbfe` green); test PRs #1 (empty change: `build` green, merge state CLEAN) and #2 (broken compilation: `build` red, merge state BLOCKED) were closed and their branches deleted. `master` is protected with the required check `build`, without `enforce_admins`, so the owner still pushes directly; private vulnerability reporting is on; Dependabot watches `github-actions`. The editor module needs only `libplasmanm_editor.so` from plasma-nm (9 unresolved `VpnUiPlugin` symbols). With `KDECMakeSettings`, CTest also runs ECM's own appstream test.
