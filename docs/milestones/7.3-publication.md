# 7.3 Publication

**Stage:** 7 · **Duration:** 1 d · **Depends on:** 7.2, 1.3 · **Needed for:** —

## Goal
Release 0.1.0 to the project's public apt repository in compliance with the core licenses, under the package names from design.md, and verify installation from the public repository, the last MVP criterion left for this milestone. Nothing is decided or renamed here: 7.3 only publishes what 7.2 accepted.

## Inputs
- The 0.1.0 candidate accepted in 7.2, under the package names from design.md (the sing-box core ships as `plasma-nm-vpn-sb`); the 1.3 release pipeline (signing in a GitHub Environment, a flat repository in the release assets, attestations, sources of the GPL cores with Go dependencies).
- The 7.2 acceptance record with the “installation from the public repository” item handed over to this milestone.
- [design.md](../design.md), sections “Packages”, “Distribution and supply chain” (the release rules, item “Core licenses”), “MVP acceptance criteria”.

## Tasks
- [ ] Package versions: `0.1.0+sb1.14.5`, `0.1.0+xray26.11.9`, `0.1.0+awg3.1.20261116`; `plasma-nm-vpn-common`, the metapackage and `plasma-nm-vpn-archive-keyring` get `0.1.0`. Check that they match the candidate accepted in 7.2.
- [ ] Tag `v0.1.0` → CI builds the packages (this is the first release of the main repository, so the pipeline takes the first-release path from 1.3: there is no previous `Packages`, nothing is carried over, every package comes from this build; check that the log says so) → the signing job in the GitHub Environment is approved manually → a draft release with all .deb files, `Packages`, the signed `InRelease`, the sing-box and `awg` sources → check the set of assets and `Filename:` against the final names → publish the draft.
- [ ] Release notes: MVP protocols, platform (Debian forky, KDE Plasma 6, amd64), a link to the README, session restart after an update, known limitations (IPv6 inside the tunnel is phase 2), core licenses.
- [ ] Check on a clean VM snapshot strictly following the README: download `plasma-nm-vpn-archive-keyring` from the release page, install it, `apt update`, `apt install plasma-nm-vpn`; connect a Hysteria2 profile to the bench with DNS 203.0.113.1 set in the “Protection” block before connecting; no new dependencies other than our packages (and `pkexec`, if 0.2 found it absent from a stock forky KDE installation; the same known exception as in 7.2). Mark this item in the 7.2 acceptance record.
- [ ] Verify the attestation of one of the .deb files (for example, `gh attestation verify <file> --repo alldevic/plasma-nm-vpn`).
- [ ] Check the README links to the public repository now that it serves the release.

## Deliverables
- The published 0.1.0 release with packages, index, GPL core sources and attestations.
- The closed “installation from the public repository” item in the acceptance record.

## Done when
- [ ] The 0.1.0 release page → the release is published (not a draft), the assets include all packages, `Packages`, `InRelease`, the sing-box and `awg` sources.
- [ ] Clean VM: installation following the README from `releases/latest/download/` of the public repository → `apt update` with no signature errors, `apt install plasma-nm-vpn` installs all core packages, the tunnel comes up.
- [ ] The published package names → exactly those in design.md (`plasma-nm-vpn-sb`, `plasma-nm-vpn-xray`, `plasma-nm-vpn-amneziawg`, …).

## Risks and notes
- Any published release of the main repository immediately becomes `latest`, so all rehearsals happen only in the test repository with the test key; only the final draft is published in the main repository.
- If a problem is found that needs a code or name change, publication stops and the change goes back through 7.2; nothing is fixed directly on the draft.
- Rolling back via apt is not possible: old versions are available only on past release pages. A bug in 0.1.0 is fixed by 0.1.1.
