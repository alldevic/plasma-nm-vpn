# 6.6 Import parsers

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 2.2, 2.5, 3.1, 4.1 · **Needed for:** 6.7

## Goal
Parsers that turn a `hysteria2://`/`hy2://` link, a `vless://` link or an AmneziaWG `.conf` into profile fields. They are the first entry point for untrusted data in the UI, so they are covered by unit tests with attack vectors and by fuzzing. The parsers depend neither on widgets nor on plasma-nm, so they can be written earlier, once 4.1 is done, in parallel with stage 5; the import UI that uses them is 6.7.

## Inputs
- [design.md](../design.md), section “plasma-nm user interface”: the MVP formats, the rule for parameters that are not in the form, and the rule that parsers and validators are C/GLib code without ki18n that return message codes with parameters.
- [design.md](../design.md), section “Profile data schema”: Hysteria2 `ports` in link format, the `dns` key, “AmneziaWG rules in the MVP”, item “Secrets” (import puts secrets from a link into `vpn.secrets`).
- [design.md](../design.md), section “Daemon security”: wg-quick keys (`PreUp`, `PostUp`, `PreDown`, `PostDown`, `SaveConfig`, `Table`) are dropped with a warning; `Address`, `DNS`, `MTU`, `Endpoint` are parsed into fields.
- The schema, validators (including the normalization of `0.0.0.0/1` + `128.0.0.0/1`), the shared C message code list, allowlist loader and fuzzing harness from 2.2, on which the parsers are built. The 2.5 outcome for `tls-pin-sha256` recorded in design.md. The allowlists: Hysteria2 `extra` (2.5), AWG 3.1 parameters (3.1), xray `extra` and `xhttp-extra` (4.1).
- The server bench from 0.3 (links and `.conf` files for test data).

## Tasks
- [x] A parser module in `plasma-nm-vpn-common` with no dependency on widgets or plasma-nm. Parse result: `vpn.data`, `vpn.secrets`, the target service type and a list of warnings; all values pass the 2.2 validators. Errors and warnings are message codes with parameters (the dropped key, the line number), never English text. This milestone adds the parser codes to the shared C code list (parser group, next to the 2.2 validator codes) and does not touch the editors; their ki18n rendering entries are added in 6.7.
- [x] `hysteria2://` and `hy2://` per the official URI scheme.
  - `auth@host:ports`; ports are carried over into `ports` as is (`443` or `443,5000-6000`).
  - `obfs`, `obfs-password`, `sni`, `insecure`, `pinSHA256` are parsed. `pinSHA256` follows the 2.5 outcome: if the pinned sing-box has no equivalent (the field is hidden in the editor and rejected by the generator), a link with `pinSHA256` produces the same “not supported in this version” error as below, because silently dropping a pin would weaken the TLS check.
  - `gecko` obfuscation, the `ech` parameter and `hysteria2+realm://` produce a clear “not supported in this version” error.
- [x] `vless://` per the XTLS standard (#716).
  - `type=xhttp` and `security=reality` are mandatory, otherwise an error.
  - `encryption`, `pbk`, `sid`, `spx`, `fp`, `sni`, `path`, `host`, `mode`, `extra` (→ `xhttp-extra`) are parsed.
  - `pcs`, `vcn` and the deprecated `allowInsecure` are not needed for Reality and are dropped with a warning.
- [x] AmneziaWG `.conf` in awg-quick format, including AmneziaVPN files. `[Interface]` and `[Peer]` sections, AWG parameters per the 3.1 allowlist, `HeaderProtectionKey` → the `awg-headerprotectionkey` secret. Per “AmneziaWG rules in the MVP”:
  - more than one `[Peer]` → rejected with a clear error;
  - the first IPv4 address is taken from `Address`, the rest are dropped with a warning;
  - IPv6 addresses in `Address` and `AllowedIPs` are dropped with a warning;
  - `0.0.0.0/1` + `128.0.0.0/1` in `AllowedIPs` → `0.0.0.0/0`, by calling the 2.2 library function that the editor (6.5) and the daemon also use, not a parser-specific rule;
  - IPv4 entries of `DNS` → `dns`; IPv6 entries and non-IP entries (search domains, which wg-quick also accepts in `DNS`) are dropped, each with a warning code; no `DNS` → `dns` stays empty (the daemon applies the defaults for a default-route tunnel and passes no DNS with never-default);
  - wg-quick keys are dropped with a warning.
- [x] Parameters that are not in the form are collected into a list: those allowed by the target core's `extra` allowlist go into `extra`, the rest are dropped with a warning. The `vless://` `extra` parameter goes into `xhttp-extra` and is checked against the `xhttp-extra` allowlist.
- [x] A link or `.conf` without secrets (for example, after an export without secrets) is parsed, and the secret fields stay empty.
- [x] An input size limit for the parsers (the same limit applies to files opened in 6.7); record it in design.md.
- [x] Unit tests:
  - links and `.conf` files for the 0.3 bench servers (in the test data);
  - each AmneziaWG rule above, including a `.conf` without `DNS` → empty `dns`;
  - known vectors: wg-quick hooks, newlines in values, paths in `extra`, control characters, truncated and overly long strings;
  - every error and warning carries a code from the parser group of the shared code list (the check that each one has a rendering entry belongs to 6.7);
  - a `.conf` with `DNS = 10.8.0.1, 2001:db8::1, corp.example` → `dns=10.8.0.1`, two warnings.
- [x] Fuzz targets for the three parsers on the 2.2 harness, seed corpus from the unit tests, a scheduled CI job.

## Deliverables
- `hysteria2://`/`hy2://`, `vless://` and `.conf` parsers with unit tests and fuzz targets.
- An entry in design.md: the input size limit for import.

## Done when
- [x] Unit tests in CI → green, including every attack vector above.
- [x] A `.conf` with `PostUp`, `Table`, IPv6 in `Address` and two IPv4 addresses → the extras are dropped, the warning list names each of them.
- [x] A `.conf` with two `[Peer]` sections, a link with `obfs=gecko` or `hysteria2+realm://` (and, if 2.5 found no equivalent, a link with `pinSHA256`) → a clear error, no fields returned.
- [x] The scheduled fuzzing job → ran and finished without crashes.

## Risks and notes
- Link formats differ incompatibly between clients; only the listed formats are supported (design.md, section “Open questions and risks”, “Risks”). Links from other clients produce an error, not a guess.
- The link fragment (`#name`) is not carried over as the profile name: `ConnectionEditorBase::setting()` overwrites the id with the name from plasma-nm's connection name field, so the parser ignores the fragment.
- Results:
  - **The module.** `common/profile/import.c`, in the GLib-only profile library: `pnv_import_service()` tells the format, and `pnv_import()` takes the target's lists (as its daemon merges them) and returns `PnvImport` (service, data, secrets, warnings). The parser group of the shared code list (`PNV_CODES_PARSER_FIRST`…`_LAST`) follows the validator group: eight errors and five warnings, each with a journal sentence. Their ki18n entries come in 6.7.
  - **Validation.** The result goes through `pnv_profile_check()`, new in `schema.c`: the parse without the required-secret check. A link without secrets imports with the secret fields empty.
  - **Input.** At most 64 KiB (design.md), valid UTF-8, trimmed for links.
  - **Hysteria2.**
    - `hysteria2://` and `hy2://`; `auth@host:ports`, with the ports carried over as written and the scheme's default 443; IPv6 hosts in brackets; `obfs`, `obfs-password`, `sni`, `insecure` (1/0/true/false).
    - `obfs=gecko`, `ech`, `pinSHA256` (2.5: no sing-box equivalent) and `hysteria2+realm://` are errors naming the feature.
    - Other parameters go into `extra` if the allowlist names them (as strings), and are dropped with a warning otherwise.
  - **VLESS.**
    - `type=xhttp` and `security=reality` are required; a missing one counts as the standard's default (tcp, none) and is an error naming the parameter.
    - The ten fields are mapped; `extra` → `xhttp-extra`, checked against its allowlist (`path` refused).
    - `pcs`, `vcn` and `allowInsecure` are dropped with a warning, like other parameters the form lacks.
  - **AmneziaWG.**
    - `[Interface]`/`[Peer]`, keys case-insensitive, `#` comments.
    - The 3.1 parameters by their names from the allowlist; `HeaderProtectionKey`, `PrivateKey` and `PresharedKey` → secrets.
    - `Address`: the first IPv4 entry (a bare address gets `/32`).
    - `DNS`: IPv4 only, each other entry a warning by index.
    - `AllowedIPs`: IPv6 dropped by index, the rest normalized by `pnv_parse_cidr4_list()`.
    - `Endpoint` → `server`/`port`; `PersistentKeepalive` (`off` → none).
    - wg-quick keys (`PreUp`, `PostUp`, `PreDown`, `PostDown`, `SaveConfig`, `Table`) → warnings; other unknown keys (`ListenPort`, `FwMark`) → warnings.
    - More than one `[Peer]` is an error.
  - **Unit tests.** `tests/unit/test_import.c`, 9 cases, with the bench-shaped links and `.conf` in `tests/unit/data/import/`:
    - the bench formats;
    - Hysteria2 details and the four unsupported features; VLESS details: dropped parameters, `xhttp-extra` allowed, not allowed and with `path`, the three `type`/`security` errors, no UUID;
    - the AmneziaWG rules: the Done-when `.conf` with `PostUp`, `Table`, IPv6 and two IPv4 addresses, whose warnings name each; the split route; `DNS = 10.8.0.1, 2001:db8::1, corp.example` → `dns=10.8.0.1` with two warnings; no `DNS`; no secrets; two peers; an out-of-range parameter; a duplicate key; malformed lines;
    - the vectors: newlines and control characters (encoded and raw), an `=` in a tag chain, an encoded NUL, broken encoding, truncated links, a path segment, a duplicate parameter, over 64 KiB, an over-long value, invalid UTF-8, other schemes;
    - every result's codes in the validator or parser group, and every parser code named.
  - **Fuzzing.** `tests/fuzz/fuzz_import.c` built three times (`fuzz-import-hysteria2`, `-vless`, `-amneziawg`), each prefixing its format's opening to the input. Each checks that problems render on one line within the groups, that values have no line breaks and are valid UTF-8, and that warnings are parser codes. Seed corpora come from the test data. The weekly job runs them too. Locally, a minute each in the VM: 357 000, 520 000 and 575 000 runs, no crash.
  - CI: build green (`import` in the unit tests); the fuzz workflow, dispatched with the full 30 minutes per target, finished all five targets (`profile`, `extra` and the three import targets) without a crash.
