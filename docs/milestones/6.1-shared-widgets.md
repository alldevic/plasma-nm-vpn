# 6.1 Shared widgets

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 1.1, 0.8, 2.2 · **Needed for:** 6.2–6.5

## Goal
Build the form blocks that the editors for all protocols are assembled from, so that the three MVP editors (and the phase 2 editors) do not duplicate code. The kill switch banner (6.2) goes into the same library. The blocks live in `plasma-nm-vpn-common` and do not use plasma-nm's internal API, so they are not tied to a plasma-nm version. Form validation goes through the same 2.2 validator library as the daemon, so the form and the daemon reject the same things.

## Inputs
- Repository skeleton with CMake for the editors and vendored headers (milestone 1.1); experience with the minimal `VpnUiPlugin` from milestone 0.8.
- [design.md](../design.md), section “plasma-nm user interface”: the table of blocks, the rule “form fields are the source of truth”, the boundary with the internal API (`PasswordField` is passed into the authentication block from outside), which blocks live in a protocol's own editor, value lists as core package data, validation through the 2.2 library, message codes rendered through ki18n, items “Translations” and “Build”.
- [design.md](../design.md), section “Profile data schema”: common keys and per-protocol keys.
- [design.md](../design.md), section “Leak protection”, item “Kill switch”: only for default-route tunnels; the editor cannot see never-default, so it shows a permanent hint next to the checkbox; for AmneziaWG it also disables the checkbox when `allowed-ips` has no `0.0.0.0/0`; the daemon ignores the setting with never-default.
- [design.md](../design.md), section “Architecture”, item “Service names follow the protocol, not the core”: `org.freedesktop.NetworkManager.pnv.*`.
- The validator library from milestone 2.2 (C on GLib and json-glib, in `plasma-nm-vpn-common`, no dependency on daemon code), including the allowlist loader.

## Tasks
- [x] Define a common block interface: a `QWidget` subclass with methods to load from and write to an `NMStringMap` (`vpn.data`), `isValid()`, and a change signal. Types come from NetworkManagerQt; `SettingWidget`, `PasswordField` and other plasma-nm classes are not used in the blocks.
- [x] Implement the shared blocks from the design.md table. “Reality”, “XHTTP transport” (6.4), “Obfuscation, port hopping” (6.3) and “Interface and Peer” (6.5) are not shared: each is needed by one protocol and lives in that protocol's editor.
  - “Server”: `server` and `port`. For Hysteria2, `ports` is written instead of `port`, in link format (`443` or `443,5000-6000`).
  - “TLS”: `tls-sni`, `tls-alpn`, `tls-insecure`, `tls-pin-sha256`. The pin field follows the 2.5 outcome recorded in design.md: if the pinned sing-box has no equivalent of Hysteria2's `pinSHA256` (the generator then rejects the field), a block parameter hides it and the block never writes `tls-pin-sha256`. The fingerprint field (`tls-fingerprint`) is enabled by a block parameter only for protocols over TCP (phase 2); for Hysteria2 it is hidden. Its values come from the value list the editor passes in (core package data), not from a list in the code.
  - “Authentication”: a label and a slot for the secret field (`password` or `uuid`). The editor in the core package creates the `PasswordField` and passes it into the block.
  - “Protection”: `kill-switch` (default `no`), `allow-lan` (default `yes`), `dns`. A permanent hint next to the kill switch checkbox (“The kill switch applies only when all traffic goes through the VPN”), always shown. A method to disable the checkbox with a reason, for editors that can tell the tunnel is not a default-route tunnel from their own fields (AmneziaWG `allowed-ips`, 6.5); a disabled checkbox keeps its stored value.
  - “Advanced”: `mtu` for all protocols and `extra` (JSON, sing-box and xray only, enabled by a block parameter that names the allowlist).
- [x] Link the widget library against the 2.2 validator library and call its validators for every field, including the `extra` allowlist check (the allowlist is loaded from the core package data the editor names). Field checks are not reimplemented in C++.
- [x] Message rendering: the 2.2 validators return a message code with parameters from the shared C code list (grouped by origin: validator codes from 2.2, parser codes added later by 6.6, export codes by 6.8); a single table in the widget library maps each code to an English source string via ki18n (`i18nc` with the parameters). This milestone fills in the entries for the validator codes; 6.7 adds those for the parser codes, 6.8 for the export codes. A code without an entry is shown as the code itself; the coverage test below fails for a validator code without an entry.
- [x] Strings via ki18n (`i18n`/`i18nc`, `ki18n_wrap_ui` for `.ui`), source strings in English, own `TRANSLATION_DOMAIN`. Dependency on KF6I18n.
- [x] A JSON metadata template for the UI plugin and a CMake function that fills in `Name`, `Description`, `Name[ru]`, `Description[ru]` and `X-NetworkManager-Services` (a service name of the form `org.freedesktop.NetworkManager.pnv.<protocol>`). The Russian strings are function arguments; the editors pass them in their CMake, and 7.1 supplies the final texts there. Take the remaining fields from `vpn/sstp/plasmanetworkmanagement_sstpui.json` as a model, e.g. `"Category": "VPNService"`.
- [x] QtTest tests (`QT_QPA_PLATFORM=offscreen` in CI):
  - for each block, load → write yields the same `NMStringMap`;
  - an invalid port, `ports` with garbage, a host with a newline, broken JSON in `extra` or an `extra` key outside a test allowlist make the block invalid, and the message is the rendered string, not the code;
  - in Hysteria2 mode, the “Server” block writes `ports`, not `port`, and the fingerprint in the TLS block is hidden; with the pin parameter off, the pin field is hidden and no `tls-pin-sha256` is written;
  - the kill switch hint is always visible; the disabled checkbox shows its reason and keeps its value through load → write;
  - every code in the validator group of the shared code list has an entry in the rendering table (6.7 extends this test to the parser group, 6.8 to the export group).

## Deliverables
- A widget library in `plasma-nm-vpn-common` (not linked against `libplasmanm_editor.so`), the blocks and their `.ui` files, the message code rendering table.
- The CMake function and metadata template for the 6.3–6.5 editors.
- Block unit tests in CI.

## Risks and notes
- `VpnUiPlugin::widget()` receives only the `vpn` setting, and plasma-nm builds the IPv4 tab after our widget, so the editor has no plugin-API access to `ipv4.never-default`. Hence the permanent hint rather than disabling the checkbox (design.md, “Leak protection”); the daemon ignores the kill switch with never-default and says so in the journal.
- ABI stability of the plasma-nm headers has already been checked in design.md (“Packages”) and does not need to be rechecked. The blocks do not depend on it by construction.
- Results:
  - The library: `common/widgets`, `libpnv-widgets.so`, installed by `plasma-nm-vpn-common` into `/usr/lib/<triplet>/plasma-nm-vpn/`. It links Qt6 Widgets, KF6I18n and the static `common/profile`; `ldd` shows no `libplasmanm_editor.so` (and no NetworkManagerQt either: the blocks use only its `NMStringMap` type).
  - The interface `PnvBlock`: `load()`/`write()` of an `NMStringMap`, `problems()` and `isValid()`, `changed()`. A subclass lists its fields, and the base checks each written value with `pnv_check_field()` for the block's service, with the list files the editor named merged under their prefixes. A list that does not load is a problem of the block. The problems show under the block (plain text), refreshed on every change.
  - The blocks, each with its `.ui`:
    - `PnvServerBlock`: `server` with `port`, or `ports` (`PortList`, Hysteria2);
    - `PnvTlsBlock`: SNI, ALPN, insecure. The fingerprint appears only when the editor passes the value list (entries in file order after “Default”; a value outside the list stays, for the validator to name). The pin field appears only with its parameter, which no MVP editor sets;
    - `PnvAuthBlock`: a label and the secret field passed in;
    - `PnvProtectionBlock`: the hint is always shown. `setKillSwitchDisabled(reason)` disables the checkbox with the reason and keeps its value; allow-lan is enabled only with the kill switch on;
    - `PnvAdvancedBlock`: `mtu`, and `extra` when the editor names the allowlist.
  - Checkboxes write `yes`/`no`; empty fields are dropped (empty = absent, 2.2). No field checks in C++: `grep` finds no `QValidator` or regular expression in the blocks.
  - Messages: `pnvProblemMessage()` renders a code through a ki18n table (`kli18nc`, the field's label as `%1`, positions shown from 1, names cut at 64 characters). The table has an entry for each validator code. `pnv-profile.h` marks the validator group as `PNV_CODES_VALIDATOR_FIRST`…`_LAST`, and 6.6 and 6.8 append their groups after it. A code without an entry shows its name. `TRANSLATION_DOMAIN` is `plasma-nm-vpn`.
  - Metadata: `pnv_editor_metadata()` in `cmake/PnvEditor.cmake` fills `cmake/pnv-editor.json.in` (escaping quotes and backslashes) and checks the service name. The Hysteria2 editor stub now uses it.
  - Tests: `tests/unit/widgets/test_blocks.cpp`, 17 QtTest cases offscreen. They cover load → write for every block; invalid port, ports, a host with a newline, an empty server, a DNS entry, an MTU, broken JSON and an `extra` key outside a test allowlist, each giving one rendered message under the block; the Hysteria2 mode; the pin parameter; the fingerprint list; the kill switch hint and the disabled checkbox; a missing list file; and the coverage of the validator codes. `editor-metadata` checks the generated JSON with test Russian strings that contain a quote and a backslash.
  - Found on the way: GLib's headers have members named `signals`, which Qt's keyword macros break, so the library and its users build with `QT_NO_KEYWORDS` (the vendored plasma-nm headers already use `Q_SIGNALS`). `PnvList` got a struct tag, so that C++ headers can declare it.
