# 6.5 AmneziaWG editor

**Stage:** 6 · **Duration:** 2 d · **Depends on:** 6.3, 3.2 · **Needed for:** 6.7

## Goal
An AmneziaWG profile is created in plasma-nm and connected from the applet. Obfuscation parameters are set through a table restricted by an allowlist shipped in the package, so a new AWG parameter is added by updating data, without changing the editor.

## Inputs
- Shared blocks and message code rendering from 6.1, the kill switch banner from 6.2 and the editor pattern from 6.3 (secrets, `vpn.persistent` on every save, the kill switch hint).
- The AmneziaWG daemon with routes and tests (3.1, 3.2) and the allowlist file of AWG 3.1 parameters from 3.1 (key, `awg` config name, type and allowed values).
- [design.md](../design.md), section “Profile data schema”:
  - AmneziaWG keys (`address`, `peer-public-key`, `allowed-ips`, `keepalive`, `awg-<parameter>`) and the secrets `private-key`, `preshared-key`, `awg-headerprotectionkey`; item “Secrets” (“Not required” for the optional ones);
  - `HeaderProtectionKey` outside the table;
  - “AmneziaWG rules in the MVP”, including when the tunnel counts as a default-route tunnel and the normalization of `0.0.0.0/1` + `128.0.0.0/1` to `0.0.0.0/0` by the shared 2.2 validator library (importer, editor and daemon alike).
- [design.md](../design.md), section “plasma-nm user interface”: the “Interface and Peer” block lives in this editor; MTU is in “Advanced”; AmneziaWG needs no authentication block; form validation through the 2.2 library with allowlists.
- [design.md](../design.md), section “Leak protection”, item “Kill switch”: only for default-route tunnels; a permanent hint next to the checkbox, and for AmneziaWG the checkbox is disabled when `allowed-ips` has no `0.0.0.0/0`.
- [design.md](../design.md), section “Architecture”, item “Service names follow the protocol, not the core”: `org.freedesktop.NetworkManager.pnv.amneziawg`.

## Tasks
- [x] A `VpnUiPlugin` subclass in the `plasma-nm-vpn-amneziawg` package.
  - `X-NetworkManager-Services` = `org.freedesktop.NetworkManager.pnv.amneziawg`.
  - `supportedFileExtensions()` returns an empty list, `suggestedFileName()` an empty string.
  - A constructor without side effects: the allowlist is read when the form is created, not when the plugin is loaded.
- [x] The “Interface” group: `private-key` (secret) and `address`, a single IPv4 address with a prefix, because `Ip4Config` holds only one. DNS comes from the “Protection” block (`dns`), MTU from “Advanced”; no fields are duplicated.
- [x] The “Peer” group:
  - “Server” (`server`, `port`; from `Endpoint` in the `.conf`);
  - `peer-public-key`, `preshared-key` (secret, optional);
  - `allowed-ips` (IPv4 only: IPv6 in the tunnel is phase 2), `keepalive`. The split pair `0.0.0.0/1` + `128.0.0.0/1` is normalized to `0.0.0.0/0` by the 2.2 library function that the importer (6.6) and the daemon also call; the editor does not implement its own check.
  - Keys, addresses and `allowed-ips` are checked by the 2.2 validators; messages are codes rendered by 6.1.
- [x] A “key — value” table for `awg-<parameter>`:
  - the key is chosen only from the allowlist, no free-form input;
  - the value is checked against the type and allowed values the 3.1 list specifies for that key (number, range, boolean, string for I1–I5), through the 2.2 library;
  - duplicates are not allowed.
- [x] `HeaderProtectionKey` is only the `awg-headerprotectionkey` secret, a separate `PasswordField` outside the table.
- [x] The three secrets are `PasswordField`s with `setPasswordModeEnabled(true)`, as in 6.3. Flags `private-key-flags`, `preshared-key-flags`, `awg-headerprotectionkey-flags`: StoreForUser → `AgentOwned`, StoreForAllUsers → `None`, AlwaysAsk → `NotSaved`. The default storage is the `PasswordField` default (StoreForUser when a keychain is available). The optional `preshared-key` and `awg-headerprotectionkey` also get `setPasswordNotRequiredEnabled(true)`: NotRequired → `NotRequired`, the default when the field is empty.
- [x] `askUser()` for the three secrets based on `hints`; secrets marked `NotRequired` are not asked for.
- [x] The “Protection” and “Advanced” blocks (only `mtu`, no `extra`) from 6.1, the kill switch banner from 6.2 (as in 6.3).
- [x] The kill switch: the 6.1 hint is always shown; the checkbox is disabled (6.1 disable method, with its reason) when `allowed-ips` has no `0.0.0.0/0`, and updates as `allowed-ips` is edited. never-default is not visible to the editor; the daemon ignores the kill switch then.
- [x] `setting()` writes `schema` and calls `VpnSetting::setPersistent(true)` on every save.
- [x] Strings via ki18n, source strings in English; `Name[ru]`/`Description[ru]` via the 6.1 CMake function. AWG parameter names in the table are not translated.

## Deliverables
- The AmneziaWG `VpnUiPlugin` plugin in the `plasma-nm-vpn-amneziawg` package, a parameter table driven by the allowlist data, the secrets prompt widget.

## Done when
- [x] The “Add VPN” list in the VM → an AmneziaWG entry is present, the form opens.
- [x] A profile created in the form against the amneziawg-go server on the bench from 1.4 → connects and disconnects from the applet, the handshake succeeds.
- [x] A key not in the allowlist → cannot be entered in the table. A key from the list with a value of the wrong type or out of range → the form is invalid with a readable message. Two IPv4 addresses or an IPv6 address in `address` → the form is invalid.
- [x] `nmcli -s -g vpn.data,vpn.secrets connection show <id>` → `private-key`, `preshared-key`, `awg-headerprotectionkey` are present only in `vpn.secrets`; all three show their values masked in the form.
- [x] A profile without `preshared-key` and `HeaderProtectionKey`, both set to “Not required” → connects without a secret prompt.
- [x] A test parameter added to the allowlist file in the VM → appears in the key choices without rebuilding the editor.
- [x] `nmcli -g vpn.persistent connection show <id>` for a new profile → `yes`; re-saving an existing profile keeps `vpn.persistent=yes`.
- [x] `allowed-ips=10.0.0.0/8` → the kill switch checkbox is disabled with its reason; `0.0.0.0/0` → enabled; `0.0.0.0/1, 128.0.0.0/1` → enabled and saved as `0.0.0.0/0`; in all cases the hint “The kill switch applies only when all traffic goes through the VPN” is shown.
- [x] A kill switch block produced by `kill -9` of the daemon after success, or by stopping the bench server and waiting for the cycle timeout → the banner is visible in the AmneziaWG form.

## Risks and notes
- The editor does not fill in default DNS: an empty `dns` is valid, and the daemon applies the defaults only for a default-route tunnel (design.md, “DNS”).
- With the bench server stopped, AmneziaWG detection takes about five to six minutes before the cycle starts (design.md, “Core supervision and cleanup”); allow for it in the block check. `kill -9` of the core after success does not leave a block: the reconnect cycle restores the connection.
- The AmneziaWG kernel module is not used; userspace amneziawg-go supports 3.1, no need to recheck (design.md, “Research findings”).
- Results:
  - **The editor.** `backends/awg/editor`: `AwgWidget` on the 6.4 base, with the groups:
    - “Interface”: the private key and `AwgInterfaceBlock`, one IPv4 `address`;
    - “Peer”: “Server”, `AwgPeerBlock` (public key, `allowed-ips`, keepalive) and the preshared key;
    - “AmneziaWG parameters”: the header protection key and `AwgParamsBlock`;
    - “Protection” and “Advanced” (MTU only).
    The allowlist is read when the form is created. The package `plasma-nm-vpn-amneziawg` ships the module and depends on the Qt it was built with.
  - **The parameter table.** One row per `awg-*` key: a non-editable choice of the allowlist's keys, shown by their AmneziaWG names (Jc, H1, I1…), a value and a remove button.
    - A key used in one row is disabled in the others, and “Add Parameter” takes the first unused key; it is disabled when all are used.
    - A loaded key the list lacks stays in its row for the validator to name.
    - Each value is checked by `pnv_check_field()` against the list's type, named in messages by its AmneziaWG name. The rows are refreshed after loading, since they are built without change signals.
  - **Address and allowed IPs.** `address` and `allowed-ips` go through `pnv_parse_cidr4_list()` with the editor's limits (one address; IPv4 only) via a new `PnvBlock::extraProblems()`. `allowed-ips` is saved as that function normalizes it. The kill switch checkbox follows it: disabled with “Allowed IPs do not include 0.0.0.0/0, so not all traffic goes through the VPN”, keeping its value.
  - **Secrets.** The preshared key and the header protection key, left empty with a stored option, are written as not required. The prompt asks for the secrets neither stored nor not required.
  - **Unit tests.** `tests/unit/editors/test_awg_editor.cpp`, 16 cases:
    - round trip; a new profile (both optional keys not required);
    - the key choices equal the list file and cannot be typed, and an entry added to a copied list appears;
    - no duplicates;
    - wrong values (an out-of-range uint16, a reversed range, `yes` for on/off, `#` in a chain) with readable messages;
    - two addresses or an IPv6 address are invalid;
    - the kill switch with `10.0.0.0/8`, `0.0.0.0/1, 128.0.0.0/1` (saved as `0.0.0.0/0`) and an IPv6 entry;
    - masked secrets outside `vpn.data`, a malformed preshared key; the prompt.
  - **Without a desktop.** `tests/integration/cases/test_96_awg_editor.py`, 10 cases; the driver gained `click=<button>`, which adds table rows. Checked:
    - a profile typed into the form from the bench's client config connects with a handshake; the secrets only in `[vpn-secrets]`, the preshared key not required;
    - both optional keys not required start the connection without a secret prompt;
    - the split default route is saved whole;
    - a key appended to the installed allowlist is offered without rebuilding;
    - wrong values and addresses save nothing;
    - `persistent` comes back on re-save;
    - the banner shows after `kill -9` of the daemon.
  - **On the desktop (local VM).** “AmneziaWG / AmneziaWG (plasma-nm-vpn)” is in the VPN types.
    - A new form shows the kill switch disabled with its reason next to the hint, “Add Parameter” adds a “Jc” row, and “Advanced” has MTU only. A loaded profile shows its groups with the preshared key “not required”.
    - A profile stored for all users connected from the applet with a fresh handshake and traffic through the tunnel.
    - One with the private key asked every time made kded6 show our prompt with “Private key:” only (the other two not required or stored), and connected.
    - kded6 was restarted first, since the widget library had changed under it (6.4).
