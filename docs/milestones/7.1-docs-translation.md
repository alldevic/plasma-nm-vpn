# 7.1 Documentation and translation

**Stage:** 7 · **Duration:** 2 d · **Depends on:** 6.9, 1.3 · **Needed for:** 7.2

## Goal
A third-party user with no context can install the packages, create a profile and deal with typical situations using the README, and the interface is available in Russian. It closes the MVP criterion about the README, LICENSE, `SECURITY.md`, core license information and translation. If the work does not fit into 2 d, the milestone is split by the rule in “Risks and notes”.

## Inputs
- The finished editors with import, export and the kill switch block banner (6.1–6.9); the message code rendering table (6.1); README and `SECURITY.md` drafts from 1.1; the 1.3 release pipeline and the test repository with the test key.
- [design.md](../design.md), sections “Goals and requirements” (platform, localization), “Packages” (removal and upgrades, item “plasma-nm compatibility”), “Distribution and supply chain” (items “Core licenses”, “Project license”, “Vulnerabilities”), “plasma-nm user interface” (items “Build”, “Translations”; message codes), “Leak protection” “MVP acceptance criteria”.

## Tasks
- [x] `README.md` (English) and a Russian version (for example, `README.ru.md`), linking to each other:
  - what it is, the MVP protocols and which package carries which protocol; platform: Debian forky and KDE Plasma 6, sid is supported along the way, amd64 only;
  - installation: download `plasma-nm-vpn-archive-keyring` from the GitHub release page, install it, then `apt install plasma-nm-vpn` or individual core packages. Links to the public repository appear in 7.3; until then the instructions are checked against the test repository;
  - updating: after a package update, log out and back in (kded6 and systemsettings keep the old plugin in memory);
  - creating a profile manually and by import (the “Paste link or config” field, “Open file”), exporting with the “Export” button in the editor; why plasma-nm's built-in “Import VPN connection” and export are not used (notes from 6.9);
  - kill switch (only for default-route tunnels: ignored with never-default, and for AmneziaWG unavailable without `0.0.0.0/0` in `allowed-ips`) and `allow-lan` (local networks stay reachable, but DNS to them is blocked too, so a blocked machine does not query the LAN router);
  - a “No internet after a VPN failure” section: why the block remained, the “Kill switch block active” banner with the “Clear” button in the editor, `plasma-nm-vpn-guard --clear <uuid>` (always clears that profile) and bare `--clear` (skips profiles that are connected or connecting), both with administrator rights, reboot; what to do if the server changed its IP;
  - diagnostics: `journalctl -u plasma-nm-vpn-core-<uuid>.service` and the NetworkManager log;
  - network access: only the VPN server and the liveness check through the tunnel (a DNS query to the profile's first DNS server, or to `1.1.1.1` with never-default and no DNS set), no telemetry;
  - removing the packages: removing a core package deactivates its active connections, removing `plasma-nm-vpn-common` also removes our nftables chains and `guard-status`; the `plasma-nm-vpn` system user remains after purge.
- [x] Core license information (a README section or a separate file): sing-box is GPL-3.0-or-later with the naming term (our package is `plasma-nm-vpn-sb`, none of our identifiers contains “sing-box”), sources with Go dependencies next to the release; xray is MPL-2.0 plus a link to the sources; amneziawg-go is MIT; `awg` is GPL-2.0, sources next to the release. The vendored plasma-nm headers (`vpnuiplugin.h`, `settingwidget.h`, `passwordfield.h`) are LGPL, with their license texts in the repository. The project license is MIT, with a note that the built editor together with plasma-nm's internal library forms a combined work under the GPL; the project's sources remain under MIT (design.md, item “Project license”).
- [x] `SECURITY.md`: reporting via private GitHub Security Advisories; what counts as a vulnerability (daemons running as root, a profile from an unprivileged user).
- [x] Translation, KDE-style (design.md, item “Translations”): a `Messages.sh`-like script runs `xgettext` with the ki18n keywords (`i18n`, `i18nc`, `i18np`, `i18ncp`, `ki18n*`) over the editors, the shared widgets and the message code rendering table, plus extraction from `.ui` files, into a `.pot` template; a Russian `.po`; catalogs installed with `ki18n_install`. The final `Name[ru]` and `Description[ru]` go into the 6.1 metadata template / the arguments of its CMake function in each editor, not into the generated JSON.
- [x] README dry run: a person without project context (or the implementer, strictly following the text) installs the packages in a clean VM (snapshot from 0.2) from the test repository; fix every place where they had to guess.

## Deliverables
- `README.md` and the Russian version, core license information, the final `SECURITY.md`.
- The extraction script, the translation template, the Russian `.po`, catalogs installed in the packages; `Name[ru]` and `Description[ru]` in the metadata.

## Done when
- [x] A person without context installs the packages in a clean VM following the README, from the test repository → the packages are installed, the protocol entries are visible in the “Add VPN” list, no questions about the text remain.
- [x] A system in the `ru_RU.UTF-8` locale → the editor forms, validation and import messages, the block banner, and the entry names and descriptions in the “Add VPN” list (`Name[ru]`, `Description[ru]`) are in Russian; there are no untranslated strings.
- [x] Every core in the packages and the vendored plasma-nm headers → listed in the license information with the license and a link to the sources.

## Risks and notes
- Until release 0.1.0 (7.3) is out, the public repository serves nothing: links to it in the README are checked after publication in 7.3.
- Split rule: this milestone holds two pieces of work (the READMEs with license information and `SECURITY.md`, the translation). If they do not fit into 2 d together, it is split rather than stretched, without renumbering: whichever of them does not fit becomes a further part. 7.2 waits for all parts, and plan.md gets a note about the split.
- Parser and validator messages are translatable: they are message codes rendered through ki18n by the editors (6.1, 6.6, 6.7). Daemon messages in the journal stay in English: the daemons are in C without ki18n.
- Results:
  - **Documents.** `README.md` and `README.ru.md` cover every item of the first task; the core license table and the note on the vendored plasma-nm headers are in their “Licenses” section; `SECURITY.md` asks for private GitHub Security Advisories and names what counts.
  - **Translation.** `scripts/extract-messages` builds `po/plasma-nm-vpn.pot` from the editors, the shared widgets, the message code table and the `.ui` files; `po/ru/plasma-nm-vpn.po` translates all 159 strings, with no fuzzy entries; `ki18n_install` puts the catalog into `plasma-nm-vpn-common`. `Name[ru]` and `Description[ru]` (“VPN-соединение <protocol> (plasma-nm-vpn)”) come from the editors' CMake calls.
  - **Release rehearsal.** The test repository was emptied of its releases and tags and got `v0.1.0` at `9792e70`. The pipeline built, attested and, after approval, signed and published it, with all six packages and the two GPL core sources.
  - **README dry run** on the clean snapshot from 0.2, 2026-11-28. The keyring came from the test release page, then the three README commands. `apt-get install -s plasma-nm-vpn` showed only our packages and `pkexec`. Installation ran without warnings. After a new login, all three entries appear under “VPN connections” with their descriptions, and the editors open. The one place to guess was the tab name: the README said **VPN**, while Plasma shows **VPN (hysteria2)** and the like. Both READMEs now name the tabs.
  - **Russian locale** in the same VM: `ru_RU.UTF-8` generated, Plasma's language set to Russian, new login. In Russian: the entry names and descriptions in the type list, the VLESS and AmneziaWG forms, the validation messages, the import messages (“Ничего не импортировано”, the wrong-protocol hint), and the kill switch banner on a `guard-status` entry written by hand. No untranslated strings of ours were seen. The tab titles “VPN (vless)” and the like come from plasma-nm.
  - **Found on the way.** The banner does not wrap. For a block of a deleted profile, it shows the UUID, and the page scrolls sideways even maximized. Added to the checklist's “Observations for 7.2”.
