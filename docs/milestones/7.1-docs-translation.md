# 7.1 Documentation and translation

**Stage:** 7 · **Duration:** 2 d · **Depends on:** 6.9, 0.1, 1.3 · **Needed for:** 7.2

## Goal
A third-party user with no context can install the packages, create a profile and deal with typical situations using the README, and the interface is available in Russian. The milestone starts by settling the sing-box package name, so that the README, the license information and acceptance (7.2) already use the final name. It closes the MVP criterion about the README, LICENSE, `SECURITY.md`, core license information and translation. If the work does not fit into 2 d, the milestone is split by the rule in “Risks and notes”.

## Inputs
- The answer (or its absence) in the sing-box issue from 0.1 about the package name `plasma-nm-vpn-sing-box`, and the neutral name options proposed there.
- The finished editors with import, export and the kill switch block banner (6.1–6.9); the message code rendering table (6.1); README and `SECURITY.md` drafts from 1.1; the 1.3 release pipeline and the test repository with the test key.
- [design.md](../design.md), sections “Goals and requirements” (platform, localization), “Packages” (removal and upgrades, item “plasma-nm compatibility”), “Distribution and supply chain” (items “Core licenses”, “Project license”, “Vulnerabilities”), “plasma-nm user interface” (items “Build”, “Translations”; message codes), “Leak protection”, “Open questions and risks” (“Before the first publication”), “MVP acceptance criteria”.

## Tasks
- [ ] **First, the sing-box package name** (design.md, table “Core licenses”). Read the 0.1 issue and record the outcome in design.md, closing the “Before the first publication” item.
  - Permission given → keep `plasma-nm-vpn-sing-box`; the license information links to the reply.
  - No permission or no answer → a neutral name without “sing-box”, recorded in design.md; the core is mentioned only in the package description and the license information. Update `debian/control` (the package and the `plasma-nm-vpn` metapackage dependency) and our own file names that contain “sing-box” (editor plugin, metadata, data files; the daemon is already `plasma-nm-vpn-service-sb`). The core binary and the GPL source archive keep their upstream names, and the `+sb` version suffix stays. NM service names and unit names do not change. Rebuild, rerun the affected CI tests and the installation in a clean VM from the test repository.
- [ ] `README.md` (English) and a Russian version (for example, `README.ru.md`), linking to each other, using the package names settled above:
  - what it is, the MVP protocols and which package carries which protocol; platform: Debian forky and KDE Plasma 6, sid is supported along the way, amd64 only;
  - installation: download `plasma-nm-vpn-archive-keyring` from the GitHub release page, install it, then `apt install plasma-nm-vpn` or individual core packages. Links to the public repository appear in 7.3; until then the instructions are checked against the test repository;
  - updating: after a package update, log out and back in (kded6 and systemsettings keep the old plugin in memory);
  - creating a profile manually and by import (the “Paste link or config” field, “Open file”), exporting with the “Export” button in the editor; why plasma-nm's built-in “Import VPN connection” and export are not used (notes from 6.9);
  - kill switch (only for default-route tunnels: ignored with never-default, and for AmneziaWG unavailable without `0.0.0.0/0` in `allowed-ips`) and `allow-lan` (local networks stay reachable, but DNS to them is blocked too, so a blocked machine does not query the LAN router);
  - a “No internet after a VPN failure” section: why the block remained, the “Kill switch block active” banner with the “Clear” button in the editor, `plasma-nm-vpn-guard --clear <uuid>` (always clears that profile) and bare `--clear` (skips profiles that are connected or connecting), both with administrator rights, reboot; what to do if the server changed its IP;
  - diagnostics: `journalctl -u plasma-nm-vpn-core-<uuid>.service` and the NetworkManager log;
  - network access: only the VPN server and the liveness check through the tunnel (a DNS query to the profile's first DNS server, or to `1.1.1.1` with never-default and no DNS set), no telemetry;
  - removing the packages: removing a core package deactivates its active connections, removing `plasma-nm-vpn-common` also removes our nftables chains and `guard-status`; the `plasma-nm-vpn` system user remains after purge.
- [ ] Core license information (a README section or a separate file): sing-box is GPL-3.0-or-later with the naming term and the outcome of the 0.1 issue, sources with Go dependencies next to the release; xray is MPL-2.0 plus a link to the sources; amneziawg-go is MIT; `awg` is GPL-2.0, sources next to the release. The vendored plasma-nm headers (`vpnuiplugin.h`, `settingwidget.h`, `passwordfield.h`) are LGPL, with their license texts in the repository. The project license is MIT, with a note that the built editor together with plasma-nm's internal library forms a combined work under the GPL; the project's sources remain under MIT (design.md, item “Project license”).
- [ ] `SECURITY.md`: reporting via private GitHub Security Advisories; what counts as a vulnerability (daemons running as root, a profile from an unprivileged user).
- [ ] Translation, KDE-style (design.md, item “Translations”): a `Messages.sh`-like script runs `xgettext` with the ki18n keywords (`i18n`, `i18nc`, `i18np`, `i18ncp`, `ki18n*`) over the editors, the shared widgets and the message code rendering table, plus extraction from `.ui` files, into a `.pot` template; a Russian `.po`; catalogs installed with `ki18n_install`. The final `Name[ru]` and `Description[ru]` go into the 6.1 metadata template / the arguments of its CMake function in each editor, not into the generated JSON.
- [ ] README dry run: a person without project context (or the implementer, strictly following the text) installs the packages in a clean VM (snapshot from 0.2) from the test repository; fix every place where they had to guess.

## Deliverables
- The sing-box package name settled and recorded in design.md; if renamed, the renamed packages built and installed from the test repository.
- `README.md` and the Russian version, core license information, the final `SECURITY.md`.
- The extraction script, the translation template, the Russian `.po`, catalogs installed in the packages; `Name[ru]` and `Description[ru]` in the metadata.

## Done when
- [ ] The sing-box core package name → matches the reply in the issue; without permission, none of our package names or our own file names contain “sing-box” (the core binary and the GPL source archive keep upstream names; the `+sb` suffix stays).
- [ ] A person without context installs the packages in a clean VM following the README, from the test repository → the packages are installed, the protocol entries are visible in the “Add VPN” list, no questions about the text remain.
- [ ] A system in the `ru_RU.UTF-8` locale → the editor forms, validation and import messages, the block banner, and the entry names and descriptions in the “Add VPN” list (`Name[ru]`, `Description[ru]`) are in Russian; there are no untranslated strings.
- [ ] Every core in the packages and the vendored plasma-nm headers → listed in the license information with the license and a link to the sources.

## Risks and notes
- Until release 0.1.0 (7.3) is out, the public repository serves nothing: links to it in the README are checked after publication in 7.3.
- Split rule: this milestone holds three pieces of work (the possible rename, the READMEs with license information and `SECURITY.md`, the translation). If they do not fit into 2 d together, it is split rather than stretched, without renumbering: the rename, when needed, goes first as its own short milestone (“7.1 rename”, up to 1 d: `debian/control`, our file names, rebuild, affected CI tests, installation from the test repository), and whichever of the READMEs or the translation does not fit becomes a further part. 7.2 waits for all parts, and plan.md gets a note about the split.
- Parser and validator messages are translatable: they are message codes rendered through ki18n by the editors (6.1, 6.6, 6.7). Daemon messages in the journal stay in English: the daemons are in C without ki18n.
