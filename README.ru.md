# plasma-nm-vpn

[English version](README.md)

VPN-плагины NetworkManager и редакторы KDE Plasma для трёх протоколов, устойчивых к блокировкам, с kill switch:

| Протокол | Пакет | Ядро |
|----------|-------|------|
| Hysteria2 (обфускация Salamander, смена портов) | `plasma-nm-vpn-sb` | sing-box |
| VLESS XHTTP Reality (с VLESS Encryption) | `plasma-nm-vpn-xray` | Xray |
| AmneziaWG 3.1 | `plasma-nm-vpn-amneziawg` | amneziawg-go и awg |

`plasma-nm-vpn` ставит все три; в `plasma-nm-vpn-common` лежит общее. Профили создаются и подключаются из сетевых
настроек и апплета Plasma, как любой другой VPN.

**Платформа:** Debian forky (testing) с KDE Plasma 6, amd64. Debian sid тоже работает. Другие дистрибутивы и
архитектуры не поддерживаются.

## Установка

Скачайте `plasma-nm-vpn-archive-keyring_*_all.deb` со страницы
[последнего релиза](https://github.com/alldevic/plasma-nm-vpn/releases/latest). Он добавляет ключ подписи проекта
и источник apt. Затем:

```
sudo apt install ./plasma-nm-vpn-archive-keyring_*_all.deb
sudo apt update
sudo apt install plasma-nm-vpn
```

Чтобы поставить только некоторые протоколы, ставьте их пакеты вместо `plasma-nm-vpn`, например
`sudo apt install plasma-nm-vpn-sb`.

После установки выйдите из сеанса и войдите снова (или перезагрузитесь). Настройки Plasma и её агент секретов
загружают редакторы при запуске.

Репозиторий apt лежит в файлах релиза. Около двух минут после нового релиза `apt update` может один раз завершиться
с «Hash Sum mismatch» (GitHub кеширует свои перенаправления); запустите его ещё раз. Если `apt update` продолжает
сообщать об ошибке подписи для этого репозитория, удалите устаревший частичный файл и повторите:

```
sudo rm /var/lib/apt/lists/partial/*plasma-nm-vpn*
```

### Обновление

`sudo apt update && sudo apt upgrade` обновляет пакеты вместе с ядрами. **После обновления выйдите из сеанса и
войдите снова.** Системные настройки и агент секретов Plasma (kded6) держат загруженные редакторы. Пока они не
перезапущены, тип VPN может пропасть из настроек, а запрос пароля — не появиться. Активные подключения при
обновлении продолжают работать.

## Создание профиля

Параметры системы → Wi-Fi и сеть (или сетевой апплет → Настроить) → **+** → выберите **Hysteria2**,
**VLESS XHTTP Reality** или **AmneziaWG** в разделе «VPN-соединения» → заполните вкладку **VPN (hysteria2)**,
**VPN (vless)** или **VPN (amneziawg)** → **Сохранить**. Подключайтесь из сетевого апплета.

Форма проверяет поля по мере ввода и объясняет, что не так, под группой поля; кнопка **Сохранить** неактивна, пока
форма не заполнена правильно.

**Секреты** (пароль, UUID, ключи) хранятся обычным для Plasma способом:

- «Сохранить пароль только для этого пользователя (зашифрованный)» — по умолчанию, если есть хранилище ключей
  (KWallet). Введите секрет в редакторе и сохраните. Секрет, введённый только в запросе при подключении, не
  запоминается: Plasma спросит снова.
- «Сохранить пароль для всех пользователей (незашифрованный)» — в системном файле подключения, доступном только root.
- «Запрашивать этот пароль каждый раз» — апплет спрашивает при каждом подключении.
- «Этот пароль не требуется» — для необязательных секретов (пароль обфускации Hysteria2, общий ключ и ключ защиты
  заголовков AmneziaWG).

**DNS:** укажите DNS-серверы своего VPN-провайдера в группе **Защита**. Если поле пустое и весь трафик идёт через
VPN, используются 1.1.1.1 (Cloudflare) и 9.9.9.9 (Quad9).

### Импорт и экспорт

В каждом редакторе вверху есть группа **Импорт и экспорт**:

- Вставьте в поле ссылку `hysteria2://` или `hy2://`, ссылку `vless://` или `.conf` AmneziaWG и нажмите
  **Импортировать** — или нажмите **Открыть файл…**. Форма заполнится. Всё, для чего в форме нет поля, будет
  перечислено: отброшено или перенесено в **Дополнительные параметры**, если ядро это поддерживает. Проверьте поля,
  при желании укажите DNS и сохраните. Ссылка другого протокола подскажет, какой тип VPN добавить вместо этого.
- **Экспорт…** отдаёт профиль обратно ссылкой или `.conf` — скопировать или сохранить в файл. Секреты не входят,
  пока не отмечено **Включить секреты**. Файл с секретами доступен для чтения только вам. Ссылка, скопированная с
  секретами, может остаться в истории буфера обмена. Поля, которые формат не переносит (например, kill switch),
  перечисляются.

Не поддерживаются: ссылки Hysteria2 с `obfs=gecko`, `pinSHA256` или `ech`, `hysteria2+realm://`; ссылки `vless://`
с транспортом не XHTTP или защитой не Reality; файлы AmneziaWG с несколькими `[Peer]`. Импорт сообщит об этом.

Пользуйтесь полем в наших редакторах, а не пунктом Plasma **Импортировать VPN-соединение...**. Импорт Plasma работает
только с файлами и отдаёт `.conf` WireGuard или OpenVPN. `.conf` AmneziaWG там не импортируется («NetworkManager is
missing support for OpenVPN») и профилем AmneziaWG не становится. Кнопка Plasma **Экспортировать выбранное
соединение** для наших профилей неактивна; используйте **Экспорт…** в редакторе.

## Kill switch

**Блокировать трафик в обход VPN (kill switch)** в группе **Защита** не даёт трафику уйти мимо туннеля, когда он
падает. Пока VPN переподключается после смены сети или после сна, напрямую ничего не уходит. Если подключение не
удаётся восстановить, блокировка остаётся, пока вы её не снимете.

- Она действует, только когда весь трафик идёт через VPN. С «Использовать только для ресурсов этого соединения» на
  вкладке IPv4 она не применяется (в журнале об этом есть запись). В AmneziaWG она недоступна, пока в
  **Разрешённые IP** нет `0.0.0.0/0`.
- **Разрешить локальную сеть во время блокировки** (включено по умолчанию) оставляет доступной вашу локальную сеть
  (192.168.x.x, 10.x.x.x и т. п.). DNS к адресам локальной сети всё равно блокируется, чтобы заблокированная машина
  не спрашивала имена у роутера.
- Отключение вами или удаление профиля всегда снимает блокировку.

### Нет интернета после сбоя VPN

Если VPN с включённым kill switch сдался или его служба упала, блокировка остаётся намеренно. Откройте профиль в
настройках: баннер **Действует блокировка kill switch** перечисляет все заблокированные профили.

- **Снять** убирает блокировку этого профиля, запросив пароль администратора.
- **Снять все** убирает все блокировки, кроме подключений, которые сейчас активны или подключаются.
- Можно и снова подключить профиль: когда новое подключение удастся, оно примет блокировку на себя.

Из терминала: `plasma-nm-vpn-guard --clear <uuid>` снимает блокировку одного профиля (UUID —
`nmcli -g connection.uuid connection show <имя>`); `plasma-nm-vpn-guard --clear` снимает все, кроме активных и
подключающихся. Обе команды спрашивают пароль администратора. Перезагрузка тоже снимает все блокировки.

Если сервер сменил IP-адрес: под блокировкой VPN может достучаться только до адреса, который использовал последним.
Сначала снимите блокировку, потом подключайтесь, чтобы новый адрес был найден.

## Диагностика

- Демон: `journalctl -t plasma-nm-vpn-service-sb` (или `-service-xray`, `-service-awg`);
- ядро подключения: `journalctl -u plasma-nm-vpn-core-<uuid>.service`;
- NetworkManager: `journalctl -u NetworkManager`.

Секреты в эти журналы не попадают.

## Сетевые обращения

Плагины подключаются к VPN-серверу и больше никуда. Через туннель они раз в минуту проверяют, что он работает:
DNS-запросом к первому DNS-серверу профиля (к 1.1.1.1, если в профиле нет DNS и через VPN идёт не весь трафик).
Никакой телеметрии и проверок обновлений.

## Удаление

`sudo apt remove plasma-nm-vpn-sb` (или другого пакета ядра) сначала отключает подключения этого протокола. Удаление
`plasma-nm-vpn-common` также удаляет правила файрвола kill switch и оставшиеся блокировки. Системный пользователь
`plasma-nm-vpn`, от имени которого работают ядра, остаётся после `purge`. Профили остаются в NetworkManager, пока вы
их не удалите.
